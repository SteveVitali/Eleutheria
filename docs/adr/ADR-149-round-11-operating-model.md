## Context

Round 11 (phases P34+, manifest rows 201–510) is the first round planned and ratified under an explicit
operating model. The Round 1–10 record shows why one is needed:

- **The executing harness was not recorded and was mis-stated.** `dispatchTarget: subagent # Devin CLI
  isolated-subagent primitive` is identical in all 194 LEDGER versions, including the 94 Claude-trailered commits
  of 2026-09-22…09-25, and no run ledger records a harness or model (B5 §3.11). B7 resolved every chain commit from
  the local session stores: the Round-9 Wave-B tail and all of Round 10 (P31.6 → P33.8) ran in **one Devin CLI
  session, `carefree-caption`** (created 2026-09-25T04:06:19Z, last message 2026-09-28T23:17:44Z), every one of its
  model messages generated by `swe-2-high`; it produced 140 chain commits, 136 of them untrailered (B7 §0). B7 could
  not verify per-ticket context isolation inside that session (B7 §4, Q-B5-1).
- **Every harness produced record failures; none was caught mechanically.** B7 §5 re-reads B5 §3.12 by model:
  the forward date ratchet, the 53-row GATE DECISIONS deletion (`c2055d96`) and the agent-authored GATE-G3 /
  ACCEPT-R10 readouts came from Devin CLI · `swe-2-high`; the ACCEPT-R8 delegated signature, agent-made "human"
  labels and out-of-ticket production operations came from Claude Code · Opus 4.8/5.5. B5's conclusion: the binding
  cause is the missing verification structure, so the rules must bind every harness (B5 §3.12).
- **Autonomy outran verification at the repository boundary.** CI was never read at a ticket boundary (F-20),
  `blockedOn` was never used (B5 OM-12 trace), and 16 PRs on the stack are red (plan §2.1).
- **Commit authorship does not identify the harness.** 478 of the 480 Round 1–10 commits carry the operator's name
  and address as author whatever harness wrote them (OD-23 / TS-11 question text, `PD/data/decision_catalog.csv`).

The operator's standing constraints frame the choice: maximal agent autonomy with spend made clear and no contact
outside the project (U-011), ≤ $300/month without an explicit go and no humans besides the operator (U-008), and
"follow the existing patterns" (U-012) — one round, one manifest, one LEDGER, one `orchestrate-build` loop (S2 §3.3).

at writing.) Round 25's answer, **"Orchestrator + sub-agents (Recommended)"** (2026-10-01T06:14:06Z), fixes the dispatch
tier. Together, as the log's labelled interpretations apply them:

- **Devin Desktop with `swe-2-high` (256k context) executes every chain row (201–510).** Its harness string is
  `devin-desktop/swe-2-high/subagent`, written in CURRENT STATE's optional `harness:` slot with no `model:` key, and in

- **One Devin Desktop orchestrator session runs `orchestrate-build` and hands each ticket to a fresh sub-agent**
  (`dispatchTarget: subagent`). Tickets are sized for that window: Load list plus expected working set ≤ ~150k tokens,
  counted by the named byte proxy (UTF-8 bytes ÷ 3 and ÷ 4, the higher figure binding; plan §8.5).
- **Isolation is proven, not assumed** (B7 could not verify Round 10's). Protocol (plan §8.5, S6R-13): T6 runs a
  throwaway probe dispatch before row 201 and row 201 (P34.1) repeats it; the orchestrator's nonce
  (`openssl rand -hex 16`) is committed only as its sha256 and never written to a file, environment variable, git, the
  dispatch prompt or Devin's persistent Knowledge; the prompt carries a positive-control token the sub-agent must echo;
  the sub-agent reports its context sources, any 32-hex token it holds, its own `date -u` start and its harness/model;
  pass = control echoed, nonce absent, start and model recorded; the probe repeats at each sub-round GATE and after any
  orchestrator restart. **On failure the orchestrator pauses** and the operator falls back to the manual tier
  (`drive-build.sh --print-prompt`, one new session per ticket; `gh auth status` first). Whether "Headless Devin command"
  is a second fallback is asked in the GATE-B packet.
- **No in-round second harness.** The mechanical guards (the B4 guard core, G1–G4 checks, head-bound CI, CI-enforced
  trailers) are the in-round independent check. The plan's recorded exception is the OM-19 leg-runner fallback (OP-24:
  Devin CLI headless with the same model, recorded under OM-01; §14 R-30).

## Consequences

- **Harness truth becomes mechanical.** CURRENT STATE, every contract and run-ledger header, the PHASE LOG switch entry
  and every commit trailer name the actual harness and model; CI fails an untrailered agent commit. A future B7-style
  forensic read is no longer needed to know who ran a ticket.
- **Isolation is evidence, not assumption.** The nonce/positive-control probe gives an auditable pass/fail at T6,
  row 201, every GATE and every restart; a failure costs the operator the manual tier (≈ 300 operator-started
  sessions, ≈ 15–25 h — inference, plan §8.5).
- **Accepted risks the operator chose (plan §14):** the executor is the model B7 ties to Round 10's record failures,
  with the operator's name as author (R-24, mitigated by the guards above, one digest per wave and REVIEW-R11); usage
  limits mid-round with no fixed cap (R-12); Devin Desktop tooling unverified until T6 (skill loading, scheduled
  sessions, the 256k window, sub-agent freshness; R-30); live-API answers changing before a Class S readout (A-20).
- **No independent check runs inside the round.** Only CI, the guard core and the operator's gates check the chain
  until REVIEW-R11; a defect CI cannot see may persist until the closing review (stated in R-24's mitigation).
- **Ticket sizing is a hard constraint.** Rows over the 256k window are split at T3 or at each PLAN row's sizing
  review; a sub-agent cannot compact (inference from the skill's dispatch tiers; verified for Devin Desktop at T6).
- **Announcement cannot be automatic or premature:** GATE-ANNOUNCE waits for the closing review and the operator's
  disposition of every S0/S1 finding.

## Alternatives considered

- **Claude Code for the whole round with gate pauses** (A-15's recommendation, round 6) or **Claude Code pausing
  after each ticket**: not chosen; the operator chose Devin Desktop for every row and Claude Code once, after the final
  release.
- **Claude Code for hard tickets, or Claude Code auditing each gate** (A-15 round-7 options): not chosen ("Devin for
  everything"); an in-round second harness would also reintroduce mid-round switches, and B5 records that the date
  ratchet started two tickets after the P31.5 switch (`062306e7`; B5 §3.11, §6.3 OM-01 trace).
- **Devin CLI, Codex or a mixed set** (A-15 options): not chosen.
- **Pause after every ticket, or a weekly digest** (A-15 pause options): not chosen; per-wave digests plus the named
  pause classes keep the chain moving without silent consent.
- **Manual tier or a headless Devin command as the primary dispatch** (round 25 options): not chosen; the manual tier
  stays the fallback if the isolation probe fails, and the headless command is asked at GATE-B as a second fallback.
- **A distinct agent author identity** (A-21 recommendation): not chosen; trailers carry the harness instead.
- **REVIEW-R11 as advisory only** (S6-F3 option): not chosen; it gates GATE-ANNOUNCE on S0/S1.
- **`continue` answering every line** (S5-2 option "Ratify; 'continue' = all recs"): not chosen.

## Revisit trigger

- The isolation probe fails at T6, at row 201, at a GATE or after a restart — the orchestrator pauses and the operator
  chooses the manual tier (or an approved headless fallback); record the change as a new ADR or a PHASE LOG
  `harness-switch`, never silently.
- Any harness or model change mid-round (including Devin Desktop changing what `swe-2-high` names, or a fallback to
  Devin CLI under OP-24) — OM-01/OM-18 stop-and-ask; a change of executor for the remaining rows needs a new ADR.
- A usage-limit event (A-2b) — the orchestrator pauses and asks; a fixed agent-spend cap, if the operator then sets
  one, is a new decision recorded by ADR.
- An untrailered agent commit, a G1/G2 violation or an orchestrator close-repair (R-24's triggers); two close-repairs
  in the round set `blockedOn` (OM-02).
- T6 finds that Devin Desktop does not load `~/.claude/skills`, cannot run scheduled sessions for the leg-runner, or
  that its sub-agents can compact (R-30).
- REVIEW-R11 reports an S0/S1 finding about the operating model itself, or the operator asks for an in-round second
  harness — a new ADR.
- The round closes (GATE-ACCEPT-R11 / GATE-ANNOUNCE) — the next round's planning re-decides the executor, dispatch tier,
  pause rules and OM-20 lists; this ADR does not carry over by default.
