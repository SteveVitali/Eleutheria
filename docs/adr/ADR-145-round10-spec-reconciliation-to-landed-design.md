## Context

P33.5 is the Round-10/X3 tail ticket: reconcile the canonical specification to
the *landed* design, preserving prior decisions and explicit verification
domains. A spec audit against the Round-10 (and earlier) landed record found
that the requirement text drifted from landed ADRs in a bounded set of places —
each is a case where a landed decision was recorded in an ADR but the spec
source was never amended (or the spec wording predates the decision). Nothing
landed was silent: every behavioural change below already has a landed ADR;
what was missing is the spec text catching up, recorded here and applied at
`spec_src` (SIG-ENG-003), never by editing the generated spec.

This ADR changes **no behaviour**. It amends normative text so the canonical
spec is truthful about what the landed system does and honestly records which
obligations are still open. Where a recorded deviation is a *owed obligation*
rather than a design change (human labels, production exposure, intake
operation), the requirement text stands and the obligation stays in
`DEFERRALS.md` — reconciling does not mean closing.

## Decisions

The following `spec_src` amendments are applied under this ADR (each cites its
authorising landed ADR inline; Appendix G.6 carries the disposition table):

1. **Robots posture (ADR-088, executing the operator's GL-GATE-08 disposition
   2026-09-18).** The spec still read "refuse on `disallowed`/`unavailable`".
   Amended:

   - `SIG-INGEST-012` (§21.5): the RFC 9309 §2.3.1.4 *classification* layer
     (ADR-087, kept) still runs and is **recorded per host**, but a
     `disallowed` or `unretrievable` verdict no longer refuses the fetch — the
     fetch proceeds and is stamped `robots_disregarded` so the ignored refusal
     is first-class provenance, never silent. The binding access gate stays
     `ingestion_permitted`/rights review (HG-03), which robots does not
     replace; challenges and access-control evasion stay prohibited
     (SIG-INGEST-013).
   - `SIG-INGEST-036` rule 2 (§26): "honor robots.txt" rewritten to the landed
     probe-and-record posture, naming the ADR-083 documented-API allow-list
     mode (which predates ADR-088 and was never written into the policy text)
     and affirming rules 3–4 unchanged.
   - `SIG-INGEST-046b` (§23.7): the upstream-specialist robots disallow is
     honoured as a **recorded** verdict, not an enforced refusal, under the
     same ADR-088 posture; the affirmative-rights-reservation duty
     (SIG-INGEST-046c) and the ask-first Stage-0 posture stand.

2. **Tile generation (ADR-067, ADR-118).** `SIG-GEO-012` (§19.5) said PMTiles
   are "generated by tippecanoe". Landed: the production renderer is the
   pinned tippecanoe build, with a **deterministic pure-Python PMTiles v3
   fallback encoder** when it is absent (CI/local), and archives are
   **per-compartment**, never merged. Text amended to match.

3. **As-of contract on release-namespaced surfaces (ADR-132/133/144).**
   `SIG-API-005` (§37.2) required *every* read endpoint to accept
   `as_of_world`/`as_of_belief`. Landed release routes bind the as-of pair
   **structurally** — an immutable `r/<publication>` namespace pins both
   cutoffs more strongly than a defaulted parameter — and legacy
   `as_of_*`/`ruleset` selectors on those surfaces resolve through
   `sig.compat-index/1` to a real release or an honest
   invalid/unavailable/ambiguous answer, never silently ignored. Text amended
   to state the structural binding; the requirement's intent (no implicit
   "latest") is strengthened, not weakened.

4. **§55 landed-status record (ADR-142/144, the deferred-spine dispatch
   amendment, GATE-G3, ACCEPT-R10).** §55.1's execution sequence describes the
   design order; the landed build deviated at exactly one point by recorded
   operator decision — the S3 human-evaluation spine (HUMAN-H4 → P32.22a →
   HUMAN-H5 → P32.23) was deferred wholesale and the chain resumed at P32.23a
   under amended scope. §55.1 gains a dated pointer note; §55.9 gains the full
   dated record: candidate on the active provisional basis
   (`provisional-ruleset/1`, `evaluation.status=deferred`, `decision=null`,
   `applied=[]`, `mode=shadow`), the evaluator landed-but-shadow-only, the
   intake receiver landed-but-non-operational (`operational=false`, `503
   receiver_not_operating`), GATE-G3's signed reduced scope, and ACCEPT-R10's
   signature — with the deferred rows and gated live halves still OPEN
   obligations in `DEFERRALS.md`.

5. **`SIG-TRUST-009` scoped acceptance clause (ADR-144).** The requirement
   lists what a new public release requires, including tested intake operating
   ownership. The landed GATE-G3 signature was an explicitly recorded
   reduced-scope acceptance of the **bounded staging** publication —
   dossiers `mechanical_complete`/`pilot_complete=False`, intake
   non-operational, evaluation deferred — and the clause records that this
   scope was disclosed, not satisfied, and that the full criterion set remains
   the bar for production exposure (`D-R10-PUBLISH-1` stays OPEN).

6. **`SIG-TRUST-010` deferred-evaluation clause (ADR-142).** The requirement
   covers the post-evaluation case; the landed candidate consumed the
   *inconclusive* case — provisional-basis materialization with the deferred
   evaluation posture pinned in the candidate identity, unpublished by
   construction, refusing the build if the shadow gate ever reports activated.
   The clause records that a deferred-evaluation candidate cannot satisfy
   release acceptance and a later accepted evaluation re-issues under the full
   terms.

## Scope discipline

do not double-own another ticket's ids"); requirement count stays **715**.

  the full criterion set governs the live acceptance.

  silent edit.
