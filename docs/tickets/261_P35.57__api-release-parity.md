## Goal

Split the read API into the two declared basis classes so the public site and the API never disagree: **release-backed** routes answer from the current promoted release's files and carry the release identity; **live-spine** routes keep serving the spine and disclose they are newer than the site. The promotion verifier refuses a release the API cannot serve (G3 §6.4, V7).

## Interfaces and collision surface

- `api/src/api/` — the route classes change (`release` vs `live-spine`); additive fields on existing bodies, new routes under `/v1/releases/**`; the basis middleware gains the `release` kind.
- `ops/src/ops/release_publish_verify.py` — the V7 parity check joins the promotion preflight.
- Deploy/manifest files touched only for the release-file mount configuration; the Cloud Run roll itself is the live leg.

## In scope (deliverables)

1. A release-serving path for the release-backed routes — `/v1/dossier/{scope}`, `/v1/coverage/{scope}`, `/v1/export`, `/v1/changes`, `/v1/releases/**`, and the J3 `/v1/sources…` family (TX-15) — that reads the **current promoted release's files** (or `?release=<publication_id>` for any promoted release), answers `404` for an unknown scope (never a placeholder body — DR-C3-12; ACT-08 removes the placeholder), returns body `release {label, publication_id, as_of_world}`, and carries `X-SIG-Basis: release`.
2. The live-spine routes — `/v1/claim`, `/v1/entity`, `/v1/resolution`, `/v1/evidence`, `/v1/contradiction`, `/v1/task`, `/v1/crosswalk`, `/v1/search` — disclose `basis {kind: "live-spine", as_of, spine_watermark, latest_release {label, publication_id}}` with `X-SIG-Basis: live-spine`; the OpenAPI description says "newer than the site; not a citation".
3. Service routes `/` and `/health` gain `release`, `code_commit`, and `image` (digest from `SIG_IMAGE_DIGEST`, set at deploy).
4. The V7 parity check: a promotion that moves the site to a release the API cannot serve is refused in the publish preflight.
5. The live leg: after the operator's verbatim go, mount the promoted release files and roll `sig-api`; verify the route classes on the live endpoint.
6. Tests under `tests/api` covering both classes, the 404-on-unknown-scope rule, the basis fields/headers, and the V7 refusal.
7. Requirement stamps in the PR body: `SIG-REL-010`.
