# P25.1 — Live-fetch operationalization: endpoint/robots policy + document-connector content-drift hardening

## Why this exists (findings from the P24.1 live deploy)

The live-target plumbing landed (ADR-082: `data/live_targets.toml` + runner wiring + tests), but two real operationalization gaps surfaced that the P21.3/P23.5 contracts assumed away:

1. **Overpass robots gate.** `sig-connectors run --source osm_overpass --mode live` against the default public endpoint (`overpass-api.de`) is **refused by SIG's own conduct layer**: that host's `robots.txt` disallows `/api/`, and `PoliteFetcher` honours robots with no circumvention (SIG-INGEST-037, RISK-P0-06). The OSM fetch is blocked on a **policy/endpoint decision**, not code.
2. **Document-connector content drift.** `okc_procurement`/`okcpd_policy`/`ok_statute`/`okc_council` parse/extract were written against **hand-transcribed fixtures**, not raw live bytes. "Fetch the cited URL and emit the same claims" is only true where live content matches the fixture shape — untrue for live news/portal HTML and even for gov PDFs that get re-issued.

## In scope — deliverables

1. **Implement the adopted API-vs-crawl carve-out (ADR-083 — decided 2026-09-15).** Add a reviewed `policy.crawler` allow-list (`data/api_allowlist.toml`: host, documented endpoint, ToS basis, rate limit, `counsel_reviewed: no`) and wire `PoliteFetcher` to consult it — a host on the allow-list is API access (robots not applied to that documented endpoint; rate-limit/backoff/no-circumvention still apply; the decision stamped in the fetch record); a host **off** the allow-list stays CRAWL (robots binds). First entries: `overpass-api.de`, `catalog.data.gov`/`api.data.gov`, `www.muckrock.com`, `api.usaspending.gov`, the CivicClerk tenant host. Add a test that a non-allow-listed host still refuses (no blanket bypass). This unblocks every API source across P25.2–P25.5.
2. **OSM live fetch for real** (once (1) permits it): `osm_overpass` → OCFL capture → ODbL-compartment claims into the hosted spine; idempotent re-run adds 0; a fetch record with rate-limit/robots evidence. Close `D-LIVE.1a-1`'s OSM portion.
3. **Document-connector content-drift handling.** For each doc source: a `live_targets.toml` row with the real document URL; a **content-shape check** that fails loud (a research task / disappearance record) when live content no longer matches the parser's expected genre/shape, instead of emitting garbage or silently 0 claims; keep `shadow` replay over the committed fixtures byte-identical. Wire `okc_council` (CivicClerk tenant verified live).
4. **Report + risk:** per-source live-fetch outcomes, the robots/endpoint evidence, the content-drift decisions; risk-register entries for endpoint policy + content drift.

## Out of scope
- Flipping additional sources (HG-03) beyond the already-green OKC subset; P21.8/P21.9 sources (their own gates + tokens). Zenodo/SWH deposits (HG-07). Go-public (HG-11 + counsel).
- Any robots.txt circumvention — forbidden (SIG-INGEST-037); the only permitted paths are a permitting endpoint or an auditable, documented API allow-list carve-out.
