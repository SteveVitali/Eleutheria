## In scope — deliverables

1. **Job classes and SAs (G1-01).** From the live job list, assign every job to a class and SA: `sig-ingest-rt` (`cloudsql.client`; `objectCreator` + `objectViewer` on the restricted bucket, **no `objects.delete`**; accessor only on its own source keys), `sig-export-rt` and `sig-materialize-rt` (their buckets + `cloudsql.client`), `sig-probe-rt` (read-only), and the identities later rows use — `sig-quality-probe-rt` (P34.44b; its `sig_audit` secret accessor is granted by P34.43), `sig-release-rt` (P35.53) and `sig-status-rt` (P36.43) — created with no grants until their rows land, so the declaration never claims a grant that is not in force.
2. **Overwrite check before removing delete (SIG-STORE-048).** List the object paths each class writes and whether any write replaces an existing object (GCS needs `storage.objects.delete` to overwrite). A class that overwrites gets a prefix-scoped IAM condition recorded in an engineering ADR and a DEFERRALS row for P37.3 — never a bucket-wide delete grant.
3. **Jobs on their SAs.** Each job updated with `--service-account` (no image change; job image rolls stay out of AR-3); deploy scripts pass `--service-account` explicitly; scheduler triggers invoke with a dedicated invoker identity holding `run.invoker` on their jobs only; `sig-alerts`' invoker moves to `sig-probe-rt`.
4. **Remove `roles/editor`.** Only after a read shows no workload still uses the default compute SA, remove `roles/editor` from it; the default SA keeps no basic role.
5. **Probes.** Read-only IAM analysis shows no workload holds a basic role and an ingest identity cannot delete an object outside its grant; the next scheduled fire of one job per class is read back (AR-4) and recorded (P34.39b's table if it is still open).
