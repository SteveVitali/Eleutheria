## Goal
When a connector asserts a partner (buyer, seller, recipient, funder, applies_to, operator), the sink also writes an
L1 claim whose object is an organization **entity**. The edge and accountability materializers then have real input.
This ticket is local and fixture-proven. P31.6 does the hosted replay.

## In scope — deliverables
1. **Sink support.** `object_type='entity_ref'` claims with `object_entity` set, through P31.3's existing
   `object_resolver` seam (wire it in production; do **not** redesign it — ADR-110 Decision 6) and with the identity
   guard for org entities: every partner scheme is added to `GUARDED_SCHEMES` **with its backfill in the same change**
   (ADR-110 revisit trigger (d)). The existing checks in `claim.sql` are honoured. Additive: the existing text claims
   stay exactly as they are, and the entity-ref claim is a **separate** claim with its own content digest.
   **Digest caveat (Wave A reality):** `content_digest` covers only the claim record, not the resolver's output — so
   the emitter must emit a **distinct** record for the entity-ref claim and the resolver must return `None` for the
   text claim. Resolving the existing text record would either dedupe +0 (already on the spine) or store a new text
   record as `entity_ref`, breaking "text claims unchanged".
2. **Partner org identity (ADR-R9-ENTITYREF).** One identifier scheme for partner orgs: the existing crosswalk ids
   when present (UEI/DUNS/CAGE/FIPS/agency code), otherwise a normalized-name identifier via `normalize_org_name`.
   Partner entities are minted with `entity_type='organization'` via `EntityRef.entity_type` (plus an
   `organization` row / `cached_canonical_name` so `_label_for` labels them) — the subject-only
   `_DEFAULT_ENTITY_TYPE="deployment"` (`claim_sink.py:82`) does not apply to objects. This also feeds P31.9's peer
   class. An **ambiguity rule**: an unresolvable or ambiguous partner stays text-only. A **never-a-person rule**: a
   natural-person or sole-proprietor-shaped name mints no entity and stays text-only, and this is test-pinned
   (Part VIII).
3. **Emitters.** The procurement and accountability connectors emit entity-ref claims for
   `buyer`/`seller`/`recipient`/`funder`/`applies_to`/`operator` (the exact predicate list comes from the connector
   inventory; re-confirm). These claims carry the same evidence locators as the text claim they derive from.
4. **Registry (the procurement family of D-P30.2a-1).** Register the procurement and accountability predicates in
   `predicates.yaml`: entity-ref vs literal object kind, resolution strategy, volatility, and directness for their
   genres. Map them onto existing registry predicates where the meaning is equal. Run `make gen` + `make verify-gen`,
   and commit `ontology/generated`.
5. **Fixture proof.** Over committed fixtures, the shadow-replay diff = 0 for the text claims, entity-ref claims are
   emitted, and the P28.2/P28.6 materializers run against real-PG fixture claims (not hand-inserted `object_entity`
   rows) and produce > 0 edges and links, with a +0 re-run.

**Split seam:** (1)+(2)+(4) sink/identity/registry | (3)+(5) emitters and proof.
