## Goal
Contribution back to the ecosystem with a compliant architecture: **no direct automated OSM
writes** (human-mediated suggestion only); the OSM automated-edits compliance ADR; a published +
registered **Organised Editing activity page**; a declared **changeset hashtag** wired to the §7
leverage metric; the **contribution-path licence gate**; device observations routed to OSM/DeFlock
rather than SIG capture; and structural upstream attribution in UI, API, and exports.

## In scope — deliverables
1. **No direct automated OSM writes** anywhere — SIG-CONTRIB-014; contribution back goes through a **human-mediated suggestion workflow** (a MapRoulette cooperative challenge is the verified mechanism), the mapper applies each change in their own account with their own judgment — SIG-CONTRIB-015/015a/015b.
2. The **OSM Automated Edits Code of Conduct compliance analysis recorded as ADR-017** — SIG-CONTRIB-016/016a/016b/016c (the human-in-the-loop workflow is what keeps SIG outside the policy's scope; a genuine bulk edit would require the full proposal + community-decision path).
3. An **Organised Editing activity page** published under `Organised Editing/Activities/` and registered, disclosing coordinating org + contact, hashtag, goal, timeframe, every non-standard tool + data source with usage conditions, participating accounts, and the metrics used (task outcomes, not contributor rankings) — SIG-CONTRIB-016d/016g.
4. A declared **changeset hashtag**, required on every SIG-originated edit and **wired to the §7 leverage metric** ("operator-attribution suggestions accepted upstream"), making the contribution stream publicly auditable — SIG-CONTRIB-016e.
5. The **contribution-path licence gate**: the task builder checks, before rendering, that a source's terms permit deriving an OSM edit; a task built on an incompatible source is blocked — SIG-CONTRIB-016f.
6. **Device-observation routing** to OSM/DeFlock rather than SIG capture — SIG-CONTRIB-004.
7. **Structural upstream attribution** in UI, API responses, and exports (aggregate acknowledgement is insufficient) — SIG-CONTRIB-020; per-project correction export formats using each project's own submission channel — SIG-CONTRIB-018.

## Notes
This ticket **owns** the human-mediated-suggestion posture and its two compliance surfaces — the
Automated Edits Code (escaped by keeping a human in the loop) and the Organised Editing Guidelines
(satisfied by the activity page + hashtag), recorded in ADR-017. The design objective is to
**minimize human cost per resolution** (~one decision per device), not to maximize write volume:
SIG cannot clear the ~116,800-device operator-attribution backlog mechanically (SIG-CONTRIB-017a).
The contribution-path licence gate is **distinct** from §42.4's export gate — publishing a task that
invites a mapper into a licence breach would make SIG the proximate cause of it.
