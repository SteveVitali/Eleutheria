## Goal

Build the versioned, recorded placement rule the K4 dossier index specifies: a new `exports/placement.py` running DuckDB `spatial` (pinned into the export image — no runtime `INSTALL`; `duckdb>=1.0.0` is already an exports dependency) that evaluates the `placement@1` ruleset R1–R8 per record — located point wins over declared label, declared disagreement disclosed on both dossiers, suspected axis swaps/sign flips/null-island points fall back to declared and are flagged — and writes the per-record placement columns plus the record `jurisdiction` block into the sites files. The 166,210-record `unresolved` bucket (71.4 % of publishable subjects, a keying artefact per F-469) resolves to located placements; unplaced records become a quality state with reason counts, never a jurisdiction. The placed-at-export posture is ADR-092 compute-on-read: nothing is written back to the spine. The catalog's acceptance sketch — capstone journeys A1/O1 (K13 §8) and the page-type budget exporter — is served as data prerequisite: this row emits the placement columns the journeys' dossiers render; the journeys themselves pass at their own rows.
