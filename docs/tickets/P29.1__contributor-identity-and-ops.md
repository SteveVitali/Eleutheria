# P29.1 — Contributor identity + corrections/contribution ops (P29)

- **Semantic id:** `ACTIVATE.1` · **Phase:** 29 · **Kind:** ticket · **Tag:** p29-activate
- **base_branch:** `devin/p28-6-accountability-linkage` · **Depends on:** Round 6 landed
- **Run:** `implement-spec spec=docs/tickets/P29.1__contributor-identity-and-ops.md live_verification=true`
- **Gate status:** **HG-08 / HG-10** (contribution-back, operator). ADR-R6-IDENTITY.

## Goal
Turn on the human loop under public scrutiny with **identity minimization** (design §3): the least
identity each contribution type requires, and **no homegrown account/credential system, ever**.

## Load (cite; do not copy)
- `docs/2_canonical_design_spec.md` §36 (corrections/governance), §34/§34.1 (curation tiers/scopes), §7 (contribution-back leverage), §16.x (contributor system), §0.7 (Part VIII — curation not public).
- Code: `tasks/contributor.py` (pseudonymous, tiered), `tasks/poisoning.py` (anti-poisoning), `tasks/onboarding.py`/`lifecycle.py`/`recognition.py`, `api/curation.py` (bearer token → contributor; `CURATION_KEYS` demo store; append-only `CurationLog` actor id; `SIG_CURATION_ENABLED`; loopback), `tasks/osm_feed`/`LeverageLedger` (P21.7), the `/dispute` flow.

## In scope — deliverables
1. **Tier-token curator store (productionize):** replace the demo `CURATION_KEYS` with a real,
   **issue/invite-based**, pseudonymous tier-token store (NOT open signup); anti-poisoning + append-only
   actor-id intact; secrets env-only (HG-09).
2. **Corrections/dispute ops:** the anonymous no-account `/dispute` intake wired to append-only correction
   claims + a **takedown/corrections operator runbook** (§36 governance).
3. **OSM contribution-back live:** MapRoulette challenge + OSM changeset feed → `LeverageLedger` (P21.7),
   identity owned by OSM.
4. **ADR-R6-IDENTITY** (the three-tier model; no homegrown accounts; the safety/threat rationale).
   **Open D-R7.1-AUTH:** public authenticated contribution via **OAuth against an external IdP
   (OSM/GitHub), pseudonymous subject id + tier only, never passwords/PII** — DEFERRED, gated on
   demonstrated demand + a written moderation/abuse/safety + contributor-exposure threat plan. NOT built now.

## Out of scope
- Building a public username/password account system (forbidden by ADR-R6-IDENTITY); the detector/records
  loop (P29.2); source breadth (P29.3).

## Acceptance criteria
- [ ] the tier-token curator store is issue/invite-based + pseudonymous (no open signup); curation stays authenticated, not public, loopback (Part VIII §0.7); every write append-only with actor id *(deterministic)*
- [ ] corrections/dispute intake + takedown runbook land; OSM contribution-back loop runs live → LeverageLedger *(deterministic + live-gated)*
- [ ] ADR-R6-IDENTITY written; D-R7.1-AUTH opened; NO homegrown account/credential system added *(deterministic)*
- [ ] `make check` + build-memory green *(deterministic)*

## Cross-cutting invariants
Cited from `docs/tickets/00_MANIFEST.md`: minimal PII (no per-person data beyond a pseudonymous handle);
curation authenticated + not public (Part VIII §0.7); anti-poisoning; append-only attribution; secrets
env-only (HG-09); contribution-back is a human/gate action (HG-08/HG-10), never auto.
