## In scope — deliverables

1. **LB path rule (IaC).** A committed, dry-run-by-default script that creates a serverless NEG and backend service for `sig-api` and adds the URL-map path rule `/v1/*` → it (G3 §4.3); `--verify` diffs the live URL map against the declaration. Everything else keeps going to `sig-web`.
2. **`/intake/*` rule — written, not applied.** The IaC carries the `/intake/*` → `sig-intake` rule behind a flag that stays off: no `sig-intake` service exists, intake is e-mail-only (B-8) and P37.59 owns any receiver; until then `/intake/*` stays `sig-web`'s.
3. **`sig-api` registry mount (engineered).** A read-only gcsfuse mount of the release registry and `--release-registry /mnt/rel/registry` in the CMD (`ops/Dockerfile:112`), plus absolute or same-origin links in API HTML; proven in the composed stack against a local registry. **Not rolled to production here:** the registry's bucket is P35.53's and a `sig-api` roll changes public responses (P34.46/P35.57 roll it).
4. **`sig-web` on the P32.13 nginx.** The deploy script rolls `sig-web` by digest onto the image carrying `ops/web/nginx.conf` (withdrawal include, `/r/`, `/releases/`, `/entity/` locations); with no withdrawals and no release trees in the legacy bucket, every allow-listed route is unchanged. A runbook note says how a new withdrawal takes effect (the include is read at nginx start — inference to verify; a roll or reload is needed).
5. **Composed-stack proof.** The composed e2e answers release search and `/intake/new` through the web origin (the catalog AC) — in the composed stack only.
6. **Dark check.** A byte-compare probe of every allow-listed route (P34.10's list) on the canonical origin and the run.app URL, before and after the leg; any difference fails the leg.
