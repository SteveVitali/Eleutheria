# P26.5 — The vendor tenant universe: full enumeration + remaining platforms (P26)

- **Semantic id:** `SOURCES.5` · **Phase:** 26 · **Kind:** ticket · **Tag:** p26-sources
- **base_branch:** `devin/p26-4-credential-ingests` · **Depends on:** P26.3 (per-host robots discipline + the 76-target seed), P26.4 (credential-fed pattern)
- **Run:** `implement-spec spec=docs/tickets/P26.5__vendor-tenant-universe.md live_verification=true`
- **Gate status:** engineering under GL-GATE-06 + ADR-087 (4xx robots = no policy). Hard `Disallow` honored per host.
- **Live stage:** real per-host fetches; every outcome recorded.

## Goal
P26.3 proved one connector × N tenant hosts is the real expansion multiplier —
but the target list was a curated seed (76 hosts). The vendor universe is larger:
Legistar alone fronts ~200+ US municipalities; CivicClerk, PrimeGov, and Granicus
add hundreds more, each host with its own robots.txt. Take the enumeration to the
documented ceiling and let each host's robots decide honestly.

## In scope — deliverables
1. **Full tenant enumeration.** Build the complete per-vendor host list from
   authoritative discovery (vendor-published client lists, the DNS pattern
   `<city>.<vendor>.com`, the registry's jurisdiction register, CCOPS-covered
   cities): legistar, civicclerk, primegov, **granicus** (add a connector target
   shape if the platform's API pattern permits), plus any other multi-tenant civic
   platform found during discovery (e.g. CivicPlus agendas, iCompass/Compilatio,
   NovusAGENDA). Record the enumeration source per host.
2. **Per-host target rows.** `live_targets.toml` gains a row per reachable host
   (bounded query per the class connector's existing shape — the same
   agenda/minutes/meeting-body records, nothing new semantically).
3. **Sweep runs.** Live fetch each host through the gated runner; per-host outcome
   recorded: claims / `robots_disallowed` / `link_rotted` / `no_policy_4xx` /
   `access_restricted`. The sweep may run in bounded batches (rate/politeness
   budget); partial sweeps are honest progress — the ledger records coverage.
4. **Cadence attachment.** Hosts that yield claims get monthly cadence rows in
   `ops/cadence.toml` (the P26.1 mechanism already schedules per-source).
5. **Records.** The tenant-universe summary lands in the run ledger:
   hosts attempted / allowed / refused / claimed, and the
   registered→permitted→configured→ingested ladder re-measured.

## Out of scope
- Non-vendor-platform sources (records-request tools, bespoke portals) — separate
  expansion class; bypassing any `Disallow`; flipping unresolved-terms sources.

## Acceptance criteria
- [ ] an enumerated, sourced host list per vendor platform lands as target rows — coverage claimed only for hosts actually attempted *(deterministic + live-gated)*
- [ ] every attempted host's outcome recorded; the ingesting-source/tenant count grows by the honest number that allow *(live-gated)*
- [ ] yielding hosts get cadence rows; `sig-ops cadence --check` stays green *(deterministic)*
- [ ] `make check` + `check-build-memory` + `check_backlog` green; ladder re-measured in the run ledger *(deterministic)*
