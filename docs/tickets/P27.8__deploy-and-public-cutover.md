## In scope — deliverables
1. **Export-mode build in deploy.** The deploy/degraded build produces `web/dist` with
   `SIG_DATA_SOURCE=export` + `SIG_EXPORT_DIR` pointed at the P27.4 national export — fails loud if the
   export is absent (never a fixtures fall-back for the public build).
2. **Publish only the published compartment.** The GCS sync pushes `web/dist` + `exports/out/public`
   to the public buckets and keeps `exports/out/restricted` private — verify no ODbL/restricted or
   UNDETERMINED bytes reach a public object (Part VIII §42 compartment separation).
3. **Hosted verification.** After deploy, probe the live `sig-web` + public export manifest (the
   `sig-ops probe-hosted` targets) and confirm the real national data renders (not the demo); record
   the spine/export watermark the site was built from. The **canonical public origin is
   `https://surveillancegraph.org`** (the custom domain; P27.10 completes the DNS/TLS cut-over) — build
   and verify against that origin so launch has no canonical-URL churn (the `*.run.app` URL stays a
   documented fallback).
4. **Gate package.** Assemble the HG-01/HG-11/HG-02 publication checklist (what's going public, the
   licence compartments, the Part VIII review) for the operator; the public go is the operator's tick.
5. **Records:** `docs/build/runs/P27.8.md`, PR body, `PUBLICATION_CHECKLIST` update; RETURN PASS row for
   the gated public cut-over until ticked.
