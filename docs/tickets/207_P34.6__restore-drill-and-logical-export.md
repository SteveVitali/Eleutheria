## In scope — deliverables

1. **Drill mode** (`sig-ops backup-drill --cloudsql-clone` or a `backup.sh drill` action): PITR clone `sig-pg` → `sig-pg-drill-<STAMP>` at T (≈ 10 min ago); verify through the Cloud SQL Auth Proxy with a read-only role on both instances: append-only parity at T for every spine table (`claim`, `claim_evidence`, `evidence_capture`, `evidence_artifact`, `entity`, `ingest_run`, `ingest_run_completion`, `resolution`, `contradiction`, `coverage_record`; `spine_watermark` row equal), `sqitch status` equal, PostGIS present, API smoke against the clone (`/health` 200, one `/v1/coverage` call); RTO (clone start → verified) and RPO (T vs max(lower(sys_period))) recorded.
2. **Name-checked delete:** refuses any name not matching `sig-pg-drill-*` and refuses `sig-pg` outright (tested).
3. **Full-backup variant** (SIG-OPS-001 names point-in-time *and* a full backup): restore of the latest automated backup into a pre-created empty drill instance — built and dry-run-tested here; its first run is a queued leg (the quarterly drill) on an in-ticket go or a GATE-G4 OM-20 listing.
4. **AR-2 restore-point procedure** scripted and documented: on-demand backup + pre-state capture before any hosted write; a bucket pre-copy or versioned restore point before any bucket write (FEA-07).
5. **Monthly logical export:** `gcloud sql export sql` to `gs://…-sig-backups/pg/monthly/<YYYY-MM>/`, three newest kept (lifecycle); `pg/adhoc/` expires after 30 days; the 09-15 seed dumps relabelled by copying them to `pg/seed-2026-09-15/` with a README object (originals not deleted); the monthly cadence declared in `ops/cadence.toml` (deployed by the scheduler of record, P35.1a) and carried in the OM-19 queue until then.
6. **ADR-175 — Production data protection and restore drills** (this row is its author, plan §7): deletion protection, retain-on-delete, quarterly drill at scale and after every schema-changing deploy, monthly logical export; it qualifies ADR-081 — append `- **Status:** Qualified by ADR-175 (<date -u>)` under a `## Status updates` section of ADR-081 in the same PR (S6R-24; never an edit of its body).
