## Goal
The relational core that makes every invariant enforceable: the L0–L3 claim/evidence schema,
append-only enforcement, the resolution table with a non-overlap constraint, and row-level security —
built on the generated DDL from P01.1.

## Load
- `docs/2_canonical_design_spec.md` §16 (canonical schema): §16.1 identity-only entities, §16.2 claim table, §16.3 append-only, §16.4 resolution table, §16.5 claim evidence/qualifiers, §16.6 corrections, §16.7 EDTF encoding hooks, §16.8 access control.
- Part 0, Part I §3, Appendix C (DDL), Appendix E glossary.

## In scope — deliverables
1. **L0/L1/L2/L3 schema** per §16, using PG18 native `PERIOD` / `WITHOUT OVERLAPS` and `uuidv7()`.
2. **Append-only enforcement**: UPDATE/DELETE on `claim` revoked at the role level except closing `sys_period`; corrections as new assertions with `supersedes` (§16.6).
3. **Entity tables hold identity only** — no attribute columns (§16.1).
4. **Resolution table** as a stored decision record with an **exclusion constraint** preventing overlap (§16.4) — enforced in the DB, not application code.
5. **Row-level security** policies for sensitivity tiers, applied at the view layer (§16.8, ADR-012).
6. **No plate-capable column anywhere** — schema test (SIG-STORE-026).

- Any resolver logic that *writes* resolution rows — P08.1 (this ticket provides the table + constraints).

## Cross-cutting invariants — re-check before opening the PR
- **Defining standard (§3.1):** no unexplained dots/edges; no silent overwrites; no synthetic certainty; every node has identity; every state has time; every claim has evidence; every inference is labelled; every contradiction stays visible. *(This ticket makes "no silent overwrites" and "every state has time" physically enforceable — append-only + PERIOD/exclusion constraints are the point.)*
- **Part VIII is binding (§0.7):** no plate/trip/per-person storage or lookup; RLS sensitivity tiers enforced here, not later; officer-naming test gates any person-named claim.
- **Append-only & provenance (P1–P3):** no writable "current value" columns; raw_value preserved; corrections are new assertions, never overwrites.
- **Additive/back-compat:** this ticket owns the claim/resolution schema contract later tickets depend on; new fields optional with today's-behavior defaults.
