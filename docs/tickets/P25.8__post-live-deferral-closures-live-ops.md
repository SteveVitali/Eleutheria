2. **Software Heritage save (`D-P21.5-1` remainder, BL-029).** Run `sig-ops swh-save` (or the equivalent SWH save-now API call) against the public repo URL and record the returned save status/origin visit in the deposit ledger (`docs/build/reports/DEPOSITS.md` or its successor). SWH is a public API — no credential needed.
3. **Live egress report (`D-P21.5-1` remainder, BL-029).** Produce `sig-ops egress-report` against the real deployed footprint (GCS buckets + Cloud Run) and commit the report under `docs/build/reports/` — the actual metered-egress posture, not a synthetic one.
4. **Real alert delivery + first real probe data (`D-OBS.1-1`, BL-037).** Two halves, both live:
   - **Delivery endpoint.** Provision a real `SIG_ALERT_WEBHOOK_URL`. Preferred: a minimal `sig-alerts` Cloud Run service (unauthenticated POST is fine — it only ever receives probe alerts; no secrets, no PII) that records each received alert to an append-only ledger object in the `sig-restricted` bucket. An operator-provided external webhook is an acceptable substitute. Deliver one real alert end-to-end and record the 2xx + the ledger entry.
   - **Real probe data.** Run `sig-ops` probes/`compute_uptime` against the hosted stack (`sig-api`, `sig-web` run.app URLs) and record the first real uptime/error-budget rows — replacing the synthetic-row posture.
5. **P21.3 closeout verification (`D-P21.3-1` BL-023, `D-P21.3-2` BL-024).** Verify against the live evidence and flip to DONE only what the evidence supports: live fetches landed across sources (muckrock, usaspending, decp_fr, overpass, data.gov) and credentials were provided (`SIG_MUCKROCK_TOKEN`, `SIG_DATA_GOV_KEY`, `SIG_ZENODO_SANDBOX_TOKEN` — provided: yes, values never in files).
