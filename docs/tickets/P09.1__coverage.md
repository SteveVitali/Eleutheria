# P09.1 — Coverage, completeness, and negative space

- **Sequence:** 23 of 46
- **Phase:** 9 — Coverage and negative space
- **base_branch:** current checkout — the branch the previous ticket left checked out (stacked PR chain); `main` for P00.1
- **Depends on (must land earlier in the stack):** P08.3 (contradiction object; consumes the L3 resolution + `UNRESOLVED` outcome and the four absence states)
- **Run:** `implement-spec spec=docs/tickets/P09.1__coverage.md`

## Goal
Make negative space queryable rather than editorial: the `CoverageRecord` with `sources_searched[]`
for `searched_not_found`, a denominator on every published aggregate (enforced by test), the four
absence kinds rendered distinguishably in API and UI, freshness computed relative to predicate
volatility, and completeness estimates that either publish their violated assumptions or are omitted —
with capture–recapture prohibited outright.

## In scope — deliverables
1. **`CoverageRecord`** entity per §32.1 (`subject_id`/`subject_class`, `predicate_id`, `absence_kind` ∈ {`not_researched`, `searched_not_found`, `evidence_of_absence`, `not_applicable`}, `sources_searched[]`, `searched_at`/`searched_by`, `search_method`), with `sources_searched[]` **required** when `absence_kind = searched_not_found` — SIG-METRIC-001/002.
2. **Discovery-probe negatives retained** as `searched_not_found` coverage records (enumerated candidate identifier spaces keep their confirmed-absent members, not only the present ones) — SIG-METRIC-002a.
3. The **four absence kinds mapped to the §9.5 epistemic states** (`NOT_RESEARCHED`, `NO_EVIDENCE_FOUND`, `EVIDENCE_OF_ABSENCE`, `UNRESOLVED`) so the API and UI render them distinguishably — never collapsing `not_researched` into `searched_not_found` — SIG-TIME-010/011/012.
4. **Published denominators**: every published aggregate carries its denominator and its not-evaluable count; per-jurisdiction coverage computed and published (agencies known / with deployment evidence / with contract evidence / with portal evidence / with mapped devices, mean evidence age, open-contradiction count, weight-class distribution) — SIG-METRIC-003/004.
5. **Provenance completeness** measured and published, targeted at 100% (a shortfall is a defect list) — SIG-METRIC-005.
6. **Freshness relative to predicate volatility** (a two-year-old contract date is fresh; a two-year-old active count is historical) plus the per-source freshness surface (last successful run, last content change, status, stale-count for the predicate class) — SIG-METRIC-006/007.
7. **Completeness-estimation guardrails**: capture–recapture and multi-list log-linear estimates prohibited; the single records-derived recall exception (§32.5) constrained; publish counted quantities with named denominators / records-derived bounds / reconciliation ratios / measured recall — never a total, never an implied denominator of reality — SIG-METRIC-008/008a/008b/009/010.

## Acceptance criteria (testable; from the phase's Part X ACs, sub-set to this ticket)
- [ ] `CoverageRecord` with `sources_searched[]` **required** for `searched_not_found` — a record missing it is rejected. — *(deterministic)*
- [ ] **Every published aggregate carries a denominator** (and its not-evaluable count) — enforced by test; a bare count fails the build. — *(deterministic)*
- [ ] The four absence kinds are distinguishable in **API and UI** — a test asserts `not_researched` and `searched_not_found` do not render identically. — *(deterministic for the API contract; agentic for the UI rendering check)*
- [ ] Freshness is computed **relative to predicate volatility**, not in absolute days. — *(deterministic)*
- [ ] Any completeness estimate **publishes its violated assumptions, or is omitted**; a test asserts no capture–recapture / multi-list population estimate is ever published. — *(deterministic)*
