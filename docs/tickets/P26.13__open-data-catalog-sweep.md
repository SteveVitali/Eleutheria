# P26.13 — Open-data-catalog surveillance-dataset sweep (P26)

- **Semantic id:** `SOURCES.12` · **Phase:** 26 · **Kind:** ticket · **Tag:** p26-sources
- **base_branch:** `devin/p26-12-congress-legislation` · **Depends on:** P26.9 (the camreg connector + `socrata_rows` platform + rights-packet convention)
- **Run:** `implement-spec spec=docs/tickets/P26.13__open-data-catalog-sweep.md live_verification=true`
- **Gate status:** engineering — catalog enumeration is public API; per-dataset rights/robots evaluated honestly under the existing framework; GL-GATE-06 flips clear-licence rows.
- **Live stage:** real catalog queries + real dataset fetches into the hosted spine; per-dataset outcomes recorded.

## Goal
P26.9 hand-picked 9 camera-registry endpoints and landed 34.6k claims. The
same pattern exists across *thousands* of open-data portals — Socrata (US
municipal standard), ArcGIS Hub, CKAN/DCAT (EU/national). The catalog
discovery APIs let us enumerate every surveillance-relevant dataset instead
of hand-picking: search for camera/CCTV/ALPR/surveillance/public-safety
datasets, fetch the yielding ones through the existing camreg connectors.

## In scope — deliverables
1. **Catalog enumeration.** Query the Socrata catalog API
   (`api.us.socrata.com`), ArcGIS Hub search, and one CKAN/DCAT catalog
   (e.g., data.gov.uk or a national CKAN) for surveillance-relevant
   datasets — keyword set: camera, cctv, traffic camera, alpr, license
   plate, surveillance, public safety camera. Record the enumerated
   dataset list as a committed artifact (id, portal, title, licence,
   endpoint).
2. **Dataset qualification.** For each enumerated dataset: fetch its
   metadata; classify as camera-registry-shaped (point features w/ camera
   fields → `dot_511`/`socrata_rows` path) vs non-conforming (documents,
   aggregates — recorded as non-targets honestly).
3. **Live fetch.** Every qualifying dataset on a clear licence gets a live
   target + rights packet + GL-GATE-06 flip; the camreg connector runs it.
   Per-dataset robots checked; licence-ambiguous rows stay gated and named.
   Same media-blocklist / C1-sensitivity / record-cap rules as P26.7+.
4. **Hosted run.** `sig-ingest-camreg-*` jobs for the new targets (bounded —
   cap this ticket at a defensible batch, e.g. the top ~30 qualifying
   datasets by signal; the rest land as named deferrals for a follow-up).
   Run rows + fetch records; spine delta; idempotent re-run.
5. **Records.** the enumerated-catalog artifact under
   docs/build/reports/; live_runs/ + GCS run rows; ladder re-measured;
   `D-SOURCES.8-1` updated with the newly-enumerated gated sets.

## Out of scope
- Non-camera surveillance datasets (crime stats, 911 calls — different
  claim classes, later tickets); datasets behind API keys (named
  deferrals); feeds/video.

## Acceptance criteria
- [ ] catalog sweep enumerates ≥50 candidate datasets across ≥2 catalog APIs; the enumeration artifact is committed *(live-gated)*
- [ ] ≥10 qualifying datasets produce claims into the hosted spine; per-dataset outcomes recorded *(live-gated)*
- [ ] licence-ambiguous datasets gated + named; `make check` + build-memory green; ladder re-measured *(deterministic)*
