## Goal

Stand up the release pipeline's home without exposing a byte: the **`sig-ops release` command family** (§5.1 — `cut, build, stage, verify, classify, promote, rollback, clear-latest, withdraw, status`; each verb takes the registry lock, is resumable, writes an event, `--dry-run` by default, `--apply` required for any write), the **private `gs://…-sig-release` bucket** (versioned, 30-day noncurrent lifecycle, uniform access, no `allUsers`; `staged/{r,v,s,releases}/` + `registry/{catalog.json, compat_index.json, withdrawals.json, activations/, events/, LOCK}` + `registry/conf/<gen>/` + `status/**`), the two **IAM-only staging services** (`sig-web-staging` / `sig-api-staging` — same image digests, `--no-allow-unauthenticated`, `SIG_STAGING=1`, the identity-token probe path), and the **`sig-release` job + `sig-release-rt` service account** (the ACT-13 least-privilege pattern). A staged candidate is not publicly reachable; `stage` refuses a stale generation (the catalog AC).
