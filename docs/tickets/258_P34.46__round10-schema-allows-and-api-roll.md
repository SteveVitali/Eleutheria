## Go/no-go protocol (FEA-07; plan §5.9)

- **Thresholds, measured at L1 and re-read at the start of L2:** (a) the rehearsed ACCESS EXCLUSIVE lock on `claim_evidence` ≤ 20 min **and** ≤ 2× the P34.24b clone measurement; (b) disk headroom ≥ 2× the size of `claim_evidence` (read-only size query; the 40 GB autoresize cap of P34.3 counts); (c) `lock_timeout` set for the deploy session; (d) `sqitch plan` diff between the hosted deploy set and the rehearsed tip = 0 — otherwise L1 first re-rehearses on a fresh clone (P34.6's drill-clone pattern) and records the new numbers.
- **Over any threshold →** stop, record the measurement with `date -u`, and ask the operator: a longer announced window, or defer. No tier bump is used.
- **Degraded mode for the slot:** a `/status/` maintenance notice (new sentence → copy batch, confirmed verbatim before the slot; B-2) published through P34.10's path under the slot's go; API requests that block on the lock fail within `lock_timeout`/statement timeouts — the expected unavailability window is stated in the go request.
- **Trigger pause list:** computed at L1 from the live scheduler and `ops/cadence.toml`: every trigger whose job writes the spine (ingest, materialize, recovery, quality jobs that write) and whose next fire falls from 1 h before the slot to 1 h after its planned end; recorded in the run ledger and quoted in the go request; resumed in reverse order after verification.
