# P27.9 — Interactive React islands: map, graph, search (P27)

- **Semantic id:** `LAUNCH.9` · **Phase:** 27 · **Kind:** ticket · **Tag:** p27-launch
- **base_branch:** `devin/p27-8-deploy-and-public-cutover` · **Depends on:** P27.4 (PMTiles + network/search data), P27.6 (design system), P27.8 (the live static baseline)
- **Run:** `implement-spec spec=docs/tickets/P27.9__interactive-islands.md`
- **Gate status:** engineering — **needs a new ADR** extending the public-island allowance (supersedes/extends ADR-068; revisits A1/SIG-UI-047). Islands hydrate; content pages stay zero-JS.

## Goal
Deliver the "interactive later" half of the launch (DECISION-SPA = B): rich, cutting-edge interactive
islands — a pannable/zoomable **map** over the real PMTiles, a **network-graph** explorer, and
**search/filter** — each an explicitly opted-in React island over the otherwise-static, archivable
core, with the zero-JS tabular/list equivalent preserved as the accessible fallback.

## Load (cite; do not copy)
- `docs/2_canonical_design_spec.md` §15 (web shell), SIG-UI-036/037 (static-first), **SIG-UI-047 + A1** (the zero-JS map fold-back this revisits), ADR-068 (the `/curate/**` island exception to extend), §19.4 (coordinate precision on the map).
- Code: `web/astro.config.mjs`, `web/lighthouserc.json` (the public vs island budget matrix), `web/src/pages/{map,network}.astro` + `web/src/pages/map/style.json.ts`, `exports/src/exports/tiles.py` (PMTiles), the P27.4 network/search artifacts.

## In scope — deliverables
1. **Island runtime.** Add `@astrojs/react` (or the agreed island lib) with hydration confined to the
   named islands; content pages keep shipping **no** `<script>`. Pin the toolchain (published ≥7 days).
2. **Interactive map island.** MapLibre (or equivalent) over the P27.4 PMTiles: pan/zoom/cluster, tier-
   reduced coordinates (§19.4), popups carrying the epistemic fields + citation. The reference/tabular
   equivalent remains the no-JS fallback (progressive enhancement, not replacement).
3. **Network-graph island.** An interactive sharing-network explorer over the P27.4 network dataset;
   the list equivalent remains the fallback.
4. **Search/filter island.** Client search/filter over the published index (map sites, dossiers,
   sources); degrades to the static browse/index without JS.
5. **Budgets + a11y.** A dedicated island-page budget in `lighthouserc.json` (as `/curate/**` has);
   keyboard + screen-reader operability on every island (WCAG 2.2 AA); the ODbL attribution shown on
   the map. The **new ADR** records the island allowance + the A1/SIG-UI-047 revisit + the mitigations.
6. **Records:** `docs/build/runs/P27.9.md`, PR body, the ADR (+ index regeneration via `build-memory adr-index`).

## Out of scope
- Turning content pages into a SPA (DECISION-SPA = B rejects a full SPA); removing any no-JS fallback;
  changing export data shapes (P27.4); the public cut-over (P27.8 owns deploy).

## Acceptance criteria
- [ ] the map/graph/search islands are interactive over the real P27.4 data; each has a preserved zero-JS tabular/list/browse fallback *(deterministic + agentic)*
- [ ] islands hydrate ONLY on their pages; all other public pages still ship zero `<script>` and pass their budget *(deterministic)*
- [ ] island pages meet their dedicated lighthouse budget + WCAG 2.2 AA (keyboard + SR); ODbL attribution shown on the map *(deterministic)*
- [ ] a new ADR extends the island allowance (ADR-068) + revisits A1/SIG-UI-047 with mitigations; adr-index regenerated *(deterministic)*
- [ ] `npm --prefix web run check` + `make check` + build-memory green *(deterministic)*

## Cross-cutting invariants
Cited from `docs/tickets/00_MANIFEST.md § Cross-cutting invariants`: islands are opt-in and never
remove the no-JS/accessible fallback; WCAG 2.2 AA everywhere; ODbL attribution + coordinate precision
rules on the map; an architecture decision changes only via a new ADR (SIG-ENG-003); TypeScript stays
inside `web/`.
