## Goal
Negative space ("what we have not researched about this subject") becomes proportionate and meaningful. Each subject
is compared only with peers of its declared class and only on that class's declared tracked predicates. It is then
materialized on the hosted spine.

## In scope — deliverables
1. **Peer-class definition (ADR-R9-PEERCLASS).** Peer class = (entity_type, connector class), or another key the ADR
   justifies from the measured spine. (Wave-A/P31.5 reality: every hosted **subject** is still `deployment` —
   `claim_sink.py` `_DEFAULT_ENTITY_TYPE` `:82` is subject-only — while P31.5 mints `organization` **objects**;
   `read_negative_space` groups by `c.subject_id`, so organizations enter negative space only where they are claim
   subjects. The ADR says how that is handled.) Each class has a **declared** tracked-predicate set in a data file (e.g.
   `inference/data/peer_classes.toml`). A predicate absent from the declaration is never negative space for that
   class. Record the absence kind and search method exactly as today.
2. **Implement** the rule in `read_negative_space`. Keep the old behaviour only behind an explicit legacy flag if the
   tests need it. Otherwise replace it, and record that in the ADR.
3. **Measure first.** A read-only hosted count of would-be rows per class, committed. The total must be proportionate
   (the ADR states the bound and why), with the **projected bytes against the provisioned disk** (read live; 15 GB per ADR-107) before anything is written.
4. **Hosted.** Update `materialize.sh` so that coverage runs with class-scoped negative space (not
   `--no-negative-space`, `:85`). Run it as a Cloud Run job (digest-pinned via `pin_image_digest`), re-run +0, and read the counts back.
5. **Tests** pin: no cross-class negative space; an undeclared predicate never appears; +0 re-run; the named-denominator
   metrics are unchanged.
