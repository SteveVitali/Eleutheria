## In scope — deliverables

1. **ADR-178 — Public identifier re-key** (this row is its author, plan §7): the neutral-id rule (e.g. `camreg_<jurisdiction-slug>_<n>`, never derived from an owner handle), the alias semantics (append-only; an old id never disappears from the spine — claims keep their recorded `source_id`, P1–P3), where the restricted old→new map lives and who can read it (DR-C6-01: no public redirect that repeats a handle), what old URLs answer (the neutral page, N-5 "This identifier has changed." `4f628b89a266`), and the disclosure of retained git history (A-0.4). It quotes B-3, A-0.1 and A-0.4 verbatim with their round times, carries `## Revisit trigger`, and appends its own status lines on any landed ADR it qualifies, in the same PR (S6R-24). *(SIG-PUB-002, SIG-STORE-011)*
2. **Registry re-key at the repo tip.** A committed, idempotent script renames the handle-bearing ids (the rows whose id matches the handle list, plus the surname id; J4 NEW-6) in `sources.toml` and `camera_registry_targets.toml`, and removes the 41 e-mail-shaped owner strings and handle tokens from their non-id text (notes, agency values; A-0.1). The script reads the handle list from its gitignored path and writes only neutral values; its dry-run report counts rows, never prints a handle. *(SIG-PUB-002)*
3. **Alias resolution without a public list.** The repo carries, per renamed source, only a keyed digest of the old id (recommended: HMAC-SHA256 with a key held in Secret Manager, HG-09; ADR-178 decides keyed vs plain sha256 and records the trade-off) mapped to the neutral id; the plaintext old→new map is written only to the restricted location ADR-178 names (recommended `sig-restricted`), never committed. One resolver (in `connectors` or `exports`, the ADR names it) maps a recorded `source_id` to its neutral id; exports, tile properties, the web build and (from P34.46's roll) the API use it, so every claim recorded under an old id is published under the neutral id. *(SIG-PUB-002, SIG-STORE-011, SIG-EXPORT-006)*
4. **Every public field, not only `source_id` (TS-04):** target ids, subject / claim / permalink ids and tile properties that embed a handle are mapped by the same resolver; the one `camera_operator` value is suppressed or neutralised in exports and tiles here (its full fix is P35.26). *(SIG-PUB-002)*
5. **Old-URL page.** Old source URLs answer with the neutral N-5 page (no link to the new id, no handle in title or body); built by the web build from the digest list, listed on the P34.10 route allow-list only as the neutral page. Shipped by P34.21b's republish #2 — not published here.
6. **Correction note** (repo `docs/`, linked from the sources page copy in P34.21b): which kinds of identifiers changed, why (personal data, Part VIII), that old citations resolve to a neutral notice, and that git history retains the old strings (A-0.4 = a; disclosure is the condition that unblocks P37.55's deposits after its history scan). Its public sentences go to copy batch #2 (B-2; only N-1…N-7 ship by sha256 until GATE-G4).
7. **Crawl check (the RI-01 closure rule's tool):** a committed check that scans a build tree, an export tree, tiles, a bucket listing and the repo tip for any entry of the gitignored handle list in source ids, target ids, subject/claim/permalink ids, `camera_operator` values and tile properties, reporting counts only. P34.47 runs it live; here it runs on fixtures and the repo tip.
8. **L2 (hosted, on the verbatim go):** the insert-only hosted writes ADR-178 requires so the P34.21b re-export publishes neutral ids (see Production mutations).
