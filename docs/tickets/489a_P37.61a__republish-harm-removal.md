## The fallback transform (scripted, in-PR, auditable)

The transform script is committed engineering, never a hand-edit of the tree:

1. **The three named items.** `/visual-language/` removed → **404** (the denied-route `http-absent` probe refuses a redirect). `/editorial-standards/` replaced by a **short holding notice** — the default, ruling-authorised variant, built from sha256-allowed notice strings (`N-1` "Not yet performed." class) or otherwise unmarked holding copy. The dispute promise replaced site-wide with the ruling-named current-source wording **verbatim as plain text** — the `DL-01` sentence "Something wrong, or a privacy or safety concern? Dispute or correct this record — reports arrive by e-mail."
2. **Copy-gate discipline.** Injected content carries **no `data-copy` attributes** — attributes referencing `pending` batch rows (`IB-02`, `ES-01`–`ES-04`, `DL-01` are all `pending`) make `--apply` refuse, and stripping attributes to smuggle unconfirmed sentences past B-2 is forbidden. The current-source *honest-version* variant of `/editorial-standards/` (with its real `data-copy` rows) ships only if the operator's verbatim words inside this ticket land in the batch files' confirmation logs flipping **every row of every `data-copy` id rendered on the injected page in every committed `batch-*.md` — including site-chrome rows like `DL-01`/`CC-01` (ids collide across batches; `statuses` is last-wins)** — to `confirmed`; otherwise the holding notice stands and `D-P35.38a-1` is unaffected.
3. **Gate-swept delta.** The transformed tree must pass `assert_public_tree_content` and `assert_publish_set_secret_free`. The served 09-27 tree almost certainly carries `demo_*`/`task/new/` objects and links the sweep refuses — the transform removes every refused artifact **and every object under a `[[denied]]`/cadence `http-absent` path** (denied objects are refused only by the post-sync probe — sweeping them pre-sync is what makes the publish land clean) and **enumerates each swept item in the run ledger** as required-gate engineering. Swept engineering covers whole objects AND refusals inside surviving markup (a `demo_` href, a loopback `action`, a `data-testid="task-field-*"` demo id, an attribution-failed `.jsonl` row) when the edit excises only the refused artifact. These are the scripted path's own enforcement — they do NOT trip the path-confirm pause. **The pause still binds for:** a whole-object refusal that would remove a real content page (e.g. a secret-scan hit living inside a real page — secret hits are never auto-deleted), or any substantive edit to real content beyond excision.
4. **`/dispute/` beyond the promise string.** The served 09-27 dispute page predates the P34.17 rewrite and may carry other disabled-intake claims or a live-looking form — the transform inspects it: replace it wholesale with the honest-wording page (minus `data-copy` markers) rather than string-swap only the promise line — the replacement names the real contact path (the operator-provided `SIG_DISPUTE_EMAIL` if given, else the source's stated contact wording with no promise of an inbox); if the sweep refuses it, it is swept per (3).
5. **Transform input scope.** The dist is the whole captured tree as captured (lane objects included byte-for-byte) minus the swept delta plus the injected pages — so `status/**`/`watch/**` objects present at capture upload back identical and AC2 holds trivially; lane-exclusive objects fresher than capture are covered by the keep-set, not by the dist.
6. **Profile `required` set.** The new profile's `required` = exactly the transformed tree's emitted top-level set (never empty — an empty `required` silently weakens the broken-transform check; `load_allowlist` only validates `required ⊆ top_level`). Denied-route probes stay cadence-owned (`ops/cadence.toml` `http-absent` rows) — a profile cannot weaken them.

## In-PR engineering (both paths)

- **Dead-end contingency:** if the captured 09-27 tree carries `data-copy` attributes resolving to `pending` rows, the copy gate refuses the fallback and stripping is forbidden — record the refusal and pause for the operator rather than improvising a third path.

- **Lane-object protection — REQUIRED before any apply, derived from the pre-state listing.** `publish-web`'s `sync_tree` runs `delete_extras` against `PROTECTED_PREFIXES = ("r/","releases/","entity/","conf/")`, and the status/watch lanes write into the same `-sig-web` bucket (`SIG_STATUS_BUCKET`/`SIG_WATCH_BUCKET` in `ops/gcp/{status,watch}-publish.sh`). The lane jobs may never have run — `D-P36.43-1`/`D-P37.33-1` are OPEN `prepared_not_executed` — so the keep-set is **derived from the mandated pre-state object listing**, not asserted: it protects only **lane-exclusive** objects the listing shows (`status/{state,lane}.json`, `status/sources/*.json`, `status/archive/**`, `watch/{state,lane,watch}.json`, `watch/archive/**`) — never shared namespaces (`watch/place/**`, `watch/item/**`, `*/index.html`), which the site build also emits and where protection would freeze the site's own deletes. If the listing shows no lane-exclusive objects the guard is a no-op. The keep-rule must cover **both deletes and puts** — the site build never emits lane-exclusive names, but the fallback's dist carries captured lane bytes: without put-skips the sync could overwrite objects freshened in the capture→apply window. The write-time keep-guard gets the same belt as `is_protected_object` on the delete re-check. This fix lands in this PR with tests and rides both paths.
- **The fallback's profile pair, transform script, and restore script** land in this PR: `ops/public_routes_p37_61a_0927.toml` (transformed route set), `ops/public_routes_p37_61a_0927_prestate.toml` (admits the full captured tree — used only by the publish-web restore alternative when the captured tree passes the pre-sync gates), the scripted transform, and `ops/gcp/sig-web-restore.sh` (the named scripted rollback). A shell restore does not inherit `publish.py`'s keep-rule; it implements the same keep-set itself. Post-restore verification = the AC1 GET checks + artifact identity.
