## In scope — deliverables
1. **Tippecanoe** in the export image (a pinned version and a multi-stage build, or a separate tile-build Cloud Run job;
   recorded in ADR-R9-TILES). Per-compartment PMTiles z0–z14, attribution embedded, deterministic for a snapshot.
   The pure-Python z0 fallback remains for CI.
2. **Island on tiles.** The `/map` island layers the per-compartment archives (attribution per layer in
   `style.json`). The zero-JS fallback (the static map) is unchanged. Public content pages stay at zero `<script>`.
3. **Compression.** A repo-owned nginx config for `sig-web` (gzip, plus brotli if available) for JSON, CSS, HTML and
   SVG, with the correct `Content-Type` and range support for PMTiles, plus the **first repo-owned `sig-web` deploy
   path** (an image built from it, deployed by pinned digest via `pin_image_digest`; the current hand-made service
   config — gcsfuse mount, env, ingress — is read live and reproduced, not guessed). This ticket builds and tests it;
   **P31.16 rolls it** (it owns the `sig-web` roll).
4. **Basemap (Q8 = (a), none).** No basemap is built or referenced; the style keeps today's plain background. Record
   (b) (a self-hosted extract, sized and costed first) as the follow-up in ADR-R9-TILES; (c) (third-party, leaks
   visitor viewports) is not done.
5. **Combined `points.json` (Q9 = retire).** The island no longer fetches it and the build no longer emits it; the
   zero-JS static map is unaffected. ADR-R9-TILES records R8-1 as ending (closed at P31.16's republish, when the
   public object is removed and verified gone).
6. **Tests:** tile builder z-range and attribution; the island reads tiles (web unit test); the nginx config is linted;
   the lighthouse budgets still pass.
