# P26.11 — Surveillance-legislation depth: OpenStates 50-state keyword claims (P26)

- **Semantic id:** `SOURCES.10` · **Phase:** 26 · **Kind:** ticket · **Tag:** p26-sources
- **base_branch:** `devin/p26-10-procurement-portals` · **Depends on:** P26.4 (keyed OpenStates path working), P26.6 (surveillance-relevance vocab pattern)
- **Run:** `implement-spec spec=docs/tickets/P26.11__surveillance-legislation-depth.md live_verification=true`

- **Live stage:** real keyed API fetches into the hosted spine.

## Goal
The NCSL seed carries 108 static surveillance-statute claims (`as_of=2022-02-03`).
OpenStates tracks *live* state legislation — the same signal, current. Today the
connector emits `index_only` bill links for a narrow window. Deepen it:
keyword-filtered bill queries across all 50 states + DC/territories emit typed
`legislative_instrument`-adjacent claims (bill title/summary/status claims with
the bill record as evidence) — surveillance-relevant legislation as live claims,
not just links.

## In scope — deliverables
1. **Keyword vocab.** A reviewed surveillance-legislation vocabulary (extends the
   P26.6 set with legislative phrasing: `automated license plate`, `surveillance
   technology ordinance`, `facial recognition`, `drone`, `unmanned aerial`,
   `body-worn camera`, `shotspotter`/`acoustic gunshot`, `real-time crime`,
   `cctv`, `automatic traffic enforcement`, `geofence warrant`, `cell-site
   simulator`, `stingray`, `data broker`, `predictive policing`) — reviewed as
   data in `accountability_vocab.toml` or a sibling.
2. **50-state query plan.** Bounded per-state queries (per_page bound, current
   session window, keyword set) over the v3 API — the plan is data in the target
   row, not code. Respect API rate limits through the shared politeness layer;
   rate-limit events recorded.
3. **Claim emission.** Matching bills emit typed claims: bill title, status,
   jurisdiction, session, matched-keyword — with the bill record URL + locator
   and the verbatim matched text as `raw_value`. Whether a bill becomes an
   `index_only` link vs a typed claim is determined by the vocab's claim-shape
   map, reviewed as data — a bill is never silently promoted to a §11.14
   LegalInstrument claim (it is *proposed* law, not law).
4. **Hosted run.** `sig-ingest-openstates` (existing job, secret-bound) runs the
   widened target set; per-state outcomes recorded; spine delta measured;
   idempotent re-run proven.
5. **Records.** live_runs/ + GCS run rows; run ledger records the keyword set,
   per-state hit counts, and any rate-limit/throttle events honestly.

## Out of scope
- Federal legislation (Congress.gov — separate source/key); tracking bill text
  diffs over time (a later ticket); promoting bills to statute claims.

## Acceptance criteria
- [ ] ≥40 states queried; per-state outcomes recorded (hits / empty / rate-limited) *(live-gated)*
- [ ] matching bills emit typed claims with verbatim literals + locators into the hosted spine *(live-gated)*
- [ ] idempotent re-run; rate-limit events recorded; `make check` + build-memory green *(deterministic + live-gated)*
