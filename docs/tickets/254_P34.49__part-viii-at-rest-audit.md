## In scope — deliverables

1. **Deterministic scanner.** A committed scanner, run as a one-off job on P34.43's host (read-only capture mount, read-only DB path), that classifies each capture: F-406 classes (Overpass captures holding `user`/`uid`; Eyes on Flock `summary.top_search_reasons` free text; ArcGIS captures requested with `outFields=*` holding person, address or officer fields); the I7 S1–S9 classes for any captured member of those lanes; and SIG-PUB-002 categories (home addresses, private-person names, personal identifiers, plates, travel histories). Rules are field-name and pattern rules with tests on synthetic fixtures; no model judgment is presented as a human check.
2. **Counts-only report.** Per class × source: objects and fields flagged — never values, excerpts or samples; object ids and digests only in the restricted bucket, never in the public repo (P16).
3. **Seal or suppress (SIG-GOV-007), append-only.** Flagged material leaves every publishable tier and is retained internally under `sealed`, with decision, author ("agent, under the S5-3 pre-authorisation") and rationale (rule id) recorded. The mechanism is chosen in the ticket from what the store supports **without** `UPDATE`/`DELETE` and without a hosted sqitch change that alters an existing table or takes an ACCESS EXCLUSIVE lock: an append-only tier/seal record if the evidence tables support supersession, else a sealed-digest deny set held in the restricted bucket that every export, the API evidence paths and the release builder consult (with a test that each path refuses a sealed digest), and a new-table sqitch change for the seal register appended after L52 for P34.46's deploy. No byte is deleted, moved by delete, or overwritten.
4. **Lists for the operator.** SIG-PUB-002 categorical material is sealed and listed — counts only — for the operator's purge decision once P37.71's purge function exists (WV-11; ADR-181/189); nothing is purged here.
5. **Owed rows routed.** P37.3's off-instance copies must exclude or separately encrypt sealed material (DEFERRALS row, owner P37.3); if stored Overpass captures hold `user`/`uid`, the capture-side fix (SIG-INGEST-045e — today discarded only in `extract()`, after capture) is a DEFERRALS row whose owner the orchestrator routes, trigger: the next OSM replay fire.
