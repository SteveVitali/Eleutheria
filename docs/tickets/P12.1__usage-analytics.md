# P12.1 — Usage aggregates and the analytics boundary

- **Sequence:** 29 of 46
- **Phase:** 12 — Usage and network layer
- **base_branch:** current checkout — the branch the previous ticket left checked out (stacked PR chain); `main` for P00.1
- **Depends on (must land earlier in the stack):** P11.2 (audit_structural aggregates + configured edges), P11.1 (the audit/portal ingest that lands `UsageAggregate` and configured edges) — or the prior merged ticket if Flock is skipped per SIG-ENG-035
- **Run:** `implement-spec spec=docs/tickets/P12.1__usage-analytics.md`

## Goal
Stand up the `UsageAggregate` entity and the analytics boundary as a hard privacy line: high-volume
aggregates in **Hive-partitioned Parquet queried by DuckDB** with **no per-search or per-plate row
anywhere** (schema test), small-cell suppression that records the correct rationale (institutional
small counts still publish), aggregate partitions that join to the graph **by UUID and period only,
never by name**, and partitions registered as evidence artifacts.

## In scope — deliverables
1. **`UsageAggregate`** per §11.16 — `searching_org`/`source_org` (both required; direction is the point), `period` (min one-month granularity), `count`, `search_scope`, `reason_category` (normalized, `raw_value` retained), `audit_source_type` (the four non-interchangeable types), `coverage_period` — SIG-ONTO-037.
2. **The bright line** — no raw per-search or per-plate row in the canonical store or the analytics store; the claim schema holds **no column capable of holding a licence plate** (a schema test asserts it; a predicate whose datatype could carry plate-like values is rejected at vocabulary review) — SIG-STORE-025/026.
3. **The substrate** — high-volume aggregates live outside PostgreSQL as **Hive-partitioned Parquet queried by DuckDB**; no columnar Postgres extension adopted as canonical — SIG-STORE-027.
4. **The join** — aggregate partitions join to the graph **only via `sig_entity_id` UUIDs and period, never via names**, carrying `ingest_run_id` and `agg_ruleset_version` — SIG-STORE-028.
5. **Partitions as evidence artifacts** — registered with digests; a claim is created only when SIG asserts a summary statement about a partition and cites the partition as evidence — SIG-STORE-029.
6. **Small-cell suppression** — counts 1–4 suppressed (null + `suppressed_flag` + `k_threshold`, never zero), complementary suppression so a single suppression is not invertible, finest granularity one month; suppression records **which rationale applied** (`protects_individual` / `institutional_conduct` / `contractual`); **institutional small counts are published, not suppressed merely for being small** — SIG-STORE-030/031/032/033.

## Notes
This ticket **owns** the analytics-boundary contract: the DuckDB/Parquet substrate, the UUID+period
join rule, and the partition-as-evidence pattern that keeps the §10.1 provenance chain unbroken
across the boundary. The `institutional_conduct` vs `protects_individual` distinction (SIG-STORE-032)
is load-bearing and easy to get backwards — "three searches by an agency" is accountability
information and MUST publish; the default when the two cannot be separated is suppress-and-raise-a-
review-task. The k=5 threshold is SIG's own documented policy (SIG-STORE-033), not a claimed standard.
