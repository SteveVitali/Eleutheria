## Goal
Make the reconcile / inference / tasks / contributor objects durable: write them to the tables the DDL already defines (`contradiction`, `coverage_record`, `research_task`, and the contributor tables), keep the pure-Python value objects as the computation layer, and have the API read rows instead of recomputing — so contradictions, tasks and coverage survive restarts, carry history, and can be published from a live jurisdiction.

## In scope — deliverables
1. **DDL ↔ dataclass alignment tests** (`tests/db/test_annotation_alignment.py`): for each value object ↔ table pair, assert field names/types/nullability agree (introspect `information_schema.columns` against the dataclass fields); any mismatch is fixed by an **additive** sqitch change (new nullable column) or a dataclass alias — never by dropping a column. (LD-V05.)
2. **Repositories** (`db/src/db/annotations.py`): `ContradictionRepo`, `CoverageRepo`, `TaskRepo`, `ContributorRepo`, `AccessPathRepo` — `insert(...)` append-only (state changes are new rows with `valid_from`/`recorded_at`, matching the spine's temporal model), `latest(...)`, `history(...)`, `as_of(...)` via `db.temporal.AsOf`. No UPDATE/DELETE.
3. **Pipeline wiring:** the reconcile step (after `RESOLVE`) persists emitted contradictions with their `input_digest` (byte-identical rebuild check from P08.3 becomes a DB round-trip test); `inference.coverage` persists `CoverageRecord`s; `TaskPool.generate` persists tasks and their lifecycle transitions; contributor submissions/reverts persist. A `sig-db annotations rebuild --dsn` CLI recomputes from claims and asserts equality with stored rows (P08.3's determinism now over PG).
4. **API reads rows:** replace the compute-on-read branches in `PgReadStore` (`contradictions`, `contradiction`, `coverage_for`, `tasks`, `task`) with repository reads; keep compute-on-read as a `--recompute` diagnostic flag. Flip the P21.2-tagged xfails in `tests/e2e`.
