## Design decisions fixed by this contract

### D1 — Partitioned pytest (`make test-par`)

1. **`scripts/ci/pytest_partitions.txt`** (committed data).
   - `#` comments are allowed. Every other line is one partition: whitespace-separated repo-relative directories.
   - Exactly one line is the single token `*`, meaning "every `testpaths` entry minus the directories named on the other lines".
   - Initial content (balanced on Ground truth 3; `tests/e2e` and `tests/ops` share a line because both build or touch `web/` output when `web/node_modules` is present locally):
     1. `tests/connectors`
     2. `tests/ops tests/e2e`
     3. `docs/build/tools tests/db tests/api`
     4. `*`

     The worker may rebalance from the first partitioned run's timings, by directory only, and records why.
2. **`scripts/ci/pytest_partitions.py check [--root DIR]`** (stdlib, Python ≥ 3.11 for `tomllib`; run through `uv run python`; `--root` defaults to the repository root and is where `pyproject.toml` and the partition file are read, so tests can point it at a temporary tree; `run` takes the same option). It exits 0, or exits 2 with every reason on stderr, when any of these fails:
   - every named directory exists and lies inside a `testpaths` entry read from `pyproject.toml`;
   - no named directory equals or contains another;
   - exactly one `*` line exists, plus at least one explicit line;
   - no other token appears.
3. **`… run`** first runs `check`; any failure exits 2 and starts nothing.
   - **What it launches:** one process per partition, all at once. The command is `$PYTEST_PARTITIONS_CMD` (default `uv run pytest`), which lets tests substitute it, followed by:
     - `-p no:cacheprovider --basetemp <run>/p<k>`, with `<run>` a fresh `tempfile.mkdtemp(prefix="pytest-par-", dir=os.environ.get("RUNNER_TEMP"))` made per invocation — never a fixed name, because pytest deletes an existing `--basetemp` (a fixed name would let a nested self-test wipe a running partition);
     - the partition's directories, or for `*` one `--ignore=<dir>` per explicitly named directory.
   - **Environment:** inherited unchanged (`SIG_REQUIRE_DB_TESTS`, `TESTCONTAINERS_RYUK_DISABLED`, `SIG_GCP_PROJECT` pass through).
   - **Logs:** each process writes stdout and stderr to its own log and its exit code to its own file.
   - **When all have ended:**
     - it replays the logs in partition order, each wrapped in `::group::partition <k>: <dirs>` when `GITHUB_ACTIONS=true`;
     - it prints a summary of one line per partition (k, dirs, rc, seconds, pytest's final `=… passed …=` line) plus `nproc=<os.cpu_count()>`.
   - **Exit:** 0 only if every partition's recorded rc is 0 **and** each partition's log holds pytest's final summary line with at least one `passed` (no vacuous pass, SIG-ENG-042). Any non-zero rc, **including pytest's 5 (no tests collected)**, a missing or unparsable rc file, a missing summary line, or a crash of the runner itself gives exit 1. `PYTEST_PARTITIONS_CMD` exists only for the self-tests; it never appears in `ci.yml` or the `Makefile`.
4. **`Makefile`.**
   - A new target `test-par:` with a normal tab-indented recipe `uv run python scripts/ci/pytest_partitions.py run`, added to `.PHONY` if the Makefile declares one.
   - `ci-local` runs `$(MAKE) test-par` instead of `$(MAKE) test`, under the same env prefix.
   - `test` and `check` are **unchanged**: serial, the fast local gate.
5. **`ci.yml` `python` job.** The `Test` step's `run:` becomes `make test-par`. Its `env:` block is unchanged (`SIG_REQUIRE_DB_TESTS`, `TESTCONTAINERS_RYUK_DISABLED`, `SIG_GCP_PROJECT`). Nothing else in the job changes.
6. **Interference rule (fail-loud by construction).** A test that passes serially but fails when partitioned is an isolation defect. Fix its isolation: give it its own temp path, or move its directory onto the same line as the directory it shares state with. **Never** relax an assertion, add a skip or `xfail`, or retry.
   - A wall-clock assertion that fails only when partitioned (e.g. `tests/api/test_store_pg.py` L550 `elapsed < 2.0`, L795 `elapsed < 2.5`) is a **contention** defect: the permitted remedy is rebalancing lines (e.g. moving its directory onto the lightest line), never a threshold change; otherwise stop and ask.
   - At most **two** repair rounds. If partitioned runs are still not green twice in a row after that, revert D1's `ci.yml`/`Makefile` lines, record the evidence in the run ledger, and **stop and ask** (OM-18). The operator chooses between "keep serial and land D2 only" and "continue".

### D2 — Fixture-mode Lighthouse reuse in `web` (`scripts/ci/perf_reuse.py`)

1. **Records path.** A path that matches `^docs/(build|tickets|adr)/` and does **not** match `^docs/build/tools/`. The tools and `record_policy` are CI code, so a change to them always runs full.
2. **`fingerprint <rev>`** prints the sha256 (64 lowercase hex) of the NUL-joined `git ls-tree -r -z --full-tree <rev>` entries whose path is not a records path. Mode, type, object id and path are all hashed, so a mode change counts.
3. **`decide`** reads `CI_EVENT_NAME`, `CI_REPOSITORY`, `CI_HEAD_REPO`, `CI_PR_NUMBER`, `CI_FINGERPRINT`, `CI_IMAGE` and `CI_RECORD` (the restored record's path, possibly absent). It prints **exactly** `reuse` or `run` as the last stdout line and exits 0. Exit 2 is only for usage errors.
   - **It answers `reuse` only if all of these hold:**
     - (1) the event is `pull_request`;
     - (2) `CI_HEAD_REPO` equals `CI_REPOSITORY`, and both are non-empty;
     - (3) `CI_FINGERPRINT` is 64 hex and equals a fresh `fingerprint HEAD`;
     - (4) the record parses **strictly**: exactly the keys `schema`, `lane`, `nonrecords`, `pr`, `head`, `base`, `run`, `attempt`, `image`, each once and each matching its regex (`sig.perf-pass/1`; `web-perf-fixtures`; 64 hex; digits; 40 hex; 40 hex; digits; digits; `[A-Za-z0-9]+-[0-9][0-9A-Za-z._]*`, i.e. both `ImageOS` and `ImageVersion` non-empty). No other line, no CR, and a final newline are required;
     - (5) the record's `nonrecords` equals the fingerprint;
     - (6) the record's `pr` equals `CI_PR_NUMBER`;
     - (7) HEAD's tree holds no symlink or gitlink **anywhere** (no entry of mode `120000`/`160000`; the tree has none today) — a non-records link pointing into a records path would otherwise slip past the fingerprint;
     - (8) the **coupling lint** passes at HEAD (item 5);
     - (9) `CI_IMAGE` matches the `image` regex (both parts non-empty) and the record's `image` equals it (`$ImageOS-$ImageVersion` of the current runner), so a reused verdict never crosses a runner-image update (the image carries the Chrome `lhci` uses).
   - **Anything else answers `run`**, including any exception, which is caught, reported and answered `run`.
   - **Output:**
     - every answer emits `::notice title=ci-perf-reuse::run <run> head <sha7>` or `::notice title=ci-perf-run::<reason>`;
     - every answer appends one line to `$GITHUB_STEP_SUMMARY` when that is set.
4. **`record`** writes `$CI_RECORD_OUT` with the nine keys:
   - `nonrecords` is `fingerprint HEAD`;
   - `head` and `base` are HEAD's second and first parents, read from `git cat-file -p HEAD`. If HEAD does not have exactly two parents, it refuses with exit 1 and writes no file;
   - `pr` comes from `CI_PR_NUMBER`;
   - `run` and `attempt` come from `GITHUB_RUN_ID` and `GITHUB_RUN_ATTEMPT`;
   - `image` comes from `CI_IMAGE`; a value not matching the `image` regex (either part empty, e.g. `-` or `ubuntu24-`) refuses (exit 1, no file).
5. **Coupling lint.** Run `git grep -n -E "docs/(build|tickets|adr)/|[\"']docs[\"']" HEAD -- web ':!web/package-lock.json'` and drop a line only when every regex match on it is a `docs/build/tools/…` path. Every remaining hit (path plus the exact line text, stripped) must appear in `scripts/ci/perf_reuse_allow.txt` (one `path<TAB>stripped line text` per line, `#` comments allowed).
   - Any hit not listed answers `run`, naming the line. A test asserts the lint passes on the committed tree, so a new `web` reference to records forces an audit instead of silently disabling reuse; a listed entry that no longer matches any hit is also reported (stale allow-list), as a notice.
   - At build time, audit every listed hit and record in the run ledger, for each one, why it is not a read.
   - **A hit that is a read is a stop-and-ask:** the reuse rule would be unsound.
6. **`ci.yml` `web` job wiring** — use this YAML (the workflow shell is `bash -eo pipefail`, so every fallible command is guarded). Place (a)–(c) right after the `Install from the committed lockfile` step (before `Performance budgets`), and (e)–(f) after the job's last existing step:
   ```yaml
   - name: Perf reuse — fingerprint
     id: perffp
     working-directory: ${{ github.workspace }}
     run: |
       fp="$(python3 scripts/ci/perf_reuse.py fingerprint HEAD)" || fp=""
       echo "fp=${fp}" >> "$GITHUB_OUTPUT"
   - name: Perf reuse — restore the pass record
     if: github.event_name == 'pull_request' && steps.perffp.outputs.fp != ''
     continue-on-error: true
     uses: actions/cache/restore@v6
     with:
       path: ${{ runner.temp }}/perf-pass
       key: perf-pass-v1-${{ steps.perffp.outputs.fp }}-none
       restore-keys: perf-pass-v1-${{ steps.perffp.outputs.fp }}-
   - name: Perf reuse — decide
     id: perf
     working-directory: ${{ github.workspace }}
     env:
       CI_EVENT_NAME: ${{ github.event_name }}
       CI_REPOSITORY: ${{ github.repository }}
       CI_HEAD_REPO: ${{ github.event.pull_request.head.repo.full_name }}
       CI_PR_NUMBER: ${{ github.event.pull_request.number }}
       CI_FINGERPRINT: ${{ steps.perffp.outputs.fp }}
       CI_RECORD: ${{ runner.temp }}/perf-pass/record
     run: |
       export CI_IMAGE="${ImageOS:-}-${ImageVersion:-}"
       rc=0; out="$(python3 scripts/ci/perf_reuse.py decide)" || rc=$?
       printf '%s\n' "$out"
       if [ "$rc" -eq 0 ] && [ "$(printf '%s\n' "$out" | tail -n 1)" = "reuse" ]; then
         echo "mode=reuse" >> "$GITHUB_OUTPUT"; else echo "mode=run" >> "$GITHUB_OUTPUT"; fi
   # (d) the existing `Performance budgets (build fails on regression)` step gains exactly:
   #     if: steps.perf.outputs.mode != 'reuse'
   - name: Perf reuse — write the pass record
     id: perfrec
     if: success() && github.event_name == 'pull_request' && github.event.pull_request.head.repo.full_name == github.repository && steps.perf.outputs.mode != 'reuse' && steps.perffp.outputs.fp != ''
     continue-on-error: true
     working-directory: ${{ github.workspace }}
     env:
       CI_PR_NUMBER: ${{ github.event.pull_request.number }}
       CI_RECORD_OUT: ${{ runner.temp }}/perf-pass/record
     run: |
       export CI_IMAGE="${ImageOS:-}-${ImageVersion:-}"
       mkdir -p "$(dirname "$CI_RECORD_OUT")"
       python3 scripts/ci/perf_reuse.py record
   - name: Perf reuse — save
     if: steps.perfrec.outcome == 'success'
     continue-on-error: true
     uses: actions/cache/save@v6
     with:
       path: ${{ runner.temp }}/perf-pass
       key: perf-pass-v1-${{ steps.perffp.outputs.fp }}-${{ github.run_id }}-${{ github.run_attempt }}
   ```
   (d) is the only `if:` added to an existing step: `Performance budgets` runs on an empty or missing output. **No other existing step gains a gate.** An `(a)` failure leaves `fp` empty, so nothing is restored, `decide` answers `run`, and nothing is recorded. Re-confirm `actions/cache`'s current major at build time (v6 at authoring) and add `actions/cache/restore`/`actions/cache/save` (≥ 6) to the floor dict of `test_action_majors_target_node24` in `tests/unit/test_ci_workflows.py`.

   A reuse run never writes a record. Push, dispatch and fork runs never restore, reuse or record.

## Fail-closed rules (summary)

- **Reuse requires the exact token.** Only the exact last line `reuse` from a zero exit selects reuse. Every error, missing input, cache miss, eviction, malformed record, foreign PR, fork, non-PR event, symlink or unlisted coupling hit selects `run`.
- **Records come only from full passes.** A record is written only after a full `web` pass on a same-repository PR. A reuse run never vouches for a later head, and failures are never recorded.
- **The partition runner fails loud.** It refuses an invalid partition file (exit 2), and any partition rc ≠ 0 (pytest 5 included) or a missing rc fails the job (exit 1). It never retries.
- **The checks keep their shape.** The five check names, job-level conditions, triggers, `concurrency:` and `runs-on` are unchanged, and every job still concludes `success` or `failure` on its own merits.
