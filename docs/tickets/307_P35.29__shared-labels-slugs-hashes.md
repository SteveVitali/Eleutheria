## Goal

One derivation, everywhere: a shared `labels` module — `policy/src/policy/labels.py`, importable by the exporter and the API alike — that computes `label`, `descriptor`, `label_basis`, `url_key`, `slug` and `hash` for every public entity kind, plus the `sig.entity-label/1` per-compartment artifact (`labels/<compartment>.jsonl`). It retires the raw-id and "Unnamed deployment" fallbacks that left 82.8 % of release entities unlabelled (K0 NEW-1), applies the A-10/ADR-159 organisation rule (registry-matched organisations labelled, the rest typed "not yet reviewed", non-organisation labels ship), and screens every label, slug and literal party through the Part VIII person-name rules before any of it is emitted.

## In scope (deliverables)

1. **`policy/src/policy/labels.py`** — the one derivation: `label`, `descriptor`, `label_basis ∈ {source_name, source_title, key_name, slug_name, derived, fallback}` (+ `label_source_id`), `url_key`, `slug`, `hash`, per the K2 §3.2 per-kind table (agency programme `key_name` → parsed agency name → typed fallback; Flock portal `slug_name` → "{slug words, ST upper-cased} — Flock transparency portal"; camera/site `source_name` → `derived` → `fallback`; agenda items, notices, contracts, grants, bills, policies, events, requests per the table; **person: none — no page, node, label or slug**).
2. **Deterministic disambiguation** — within (kind, release): shared labels append `· {place}`, then `· {source}`, then `#{hash4}`; the rule is a pure function with a fixture test that no two public entities of a kind share a full display label.
3. **Slug + hash primitives** — `name-slug` per K11 §3 (ASCII-fold, `[a-z0-9]+` tokens, no scheme prefixes, `-<K4 display slug of the state>` when placed, cut at 56 characters on a token boundary); `hash` = Crockford base32 of sha256(canonical UUID text), 7 characters (35 bits), extended by one character on a collision within the slug registry, **frozen once issued and never reissued**; the hash is authoritative, the slug cosmetic (any `--<hash>` suffix resolves — §3.3).
4. **The Part VIII person-name screen over every label input** — including literal party values (procurement `seller` literals: a person-shaped value stays a text claim and is never a label input — §3.4 R-8); no label formed from coordinates finer than the published precision (§19.4) or carrying a private registrant's street address; handle-like source ids never appear in a label (the publisher display name does, or "a public …").
5. **The A-10/ADR-159 organisation rule** — organisations matched by the registry auto-allow carry their label; every other organisation renders the typed "not yet reviewed" state (the gate's words — `label_basis`/`label_state` make the typedness explicit, never a bare suppression); non-organisation labels ship unconditionally; a withheld entity (the eligibility gate) gets no label/node/slug at all.
6. **`sig.entity-label/1` — `labels/<compartment>.jsonl`** — `{entity_id, sig_id, kind, url_type, label, descriptor, label_basis, label_source_id, place_jkey, slug, hash, url, disambiguator, component_id, part8: pass|fallback}` per K2 §6.1, emitted per compartment from the export's one snapshot.
7. **Call-site rewires** — the exporter's network label lookup and `entity_labels` usage, the shaping site-label path, the release-page record builder ("Unnamed deployment" retired), and the API label path all read the module's outputs (directly or via the emitted artifact).
8. Tests: §3.2 per-kind derivations on fixtures; disambiguation determinism; the person-name screen over literal parties (a person-shaped `seller` yields no label); the withheld-entity no-label rule; the collision-extension rule for the 7-char hash; label_basis always populated; the API/exporter agreement (one function, no drift).
9. Requirement stamps in the PR body: the cited ids above (UXR-17 recorded as the draft id).
