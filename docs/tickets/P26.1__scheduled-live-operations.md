# P26.1 — Scheduled live operations: probe accumulation + source reingestion cadence (P26)

- **Semantic id:** `OPS.2` · **Phase:** 26 · **Kind:** ticket · **Tag:** p26-ops
- **base_branch:** current checkout · **Depends on:** P24.1 (deployed stack), P25.7 (live-ops hardening), P25.8 (`sig-alerts` receiver + first probe sweep)
- **Run:** `implement-spec spec=docs/tickets/P26.1__scheduled-live-operations.md live_verification=true`
- **Gate status:** engineering — no human gate. Cadence choices are operator-revisable config, not gates.
- **Live stage:** real Cloud Scheduler + Cloud Run jobs against the deployed stack; recorded evidence.

## Goal
Today every probe and every reingestion is a hand-run command — uptime data exists as a
single sweep (`docs/build/reports/probes_*.jsonl`) and live sources only refresh when
someone remembers. Make both **automatic, scheduled, and durably recorded**, consistent
with the append-only ethos: every scheduled run leaves an honest outcome row, and probe
failures route through the existing `sig-alerts` receiver.

## In scope — deliverables
1. **Scheduled probes.** A Cloud Scheduler job (e.g. every 6h) invoking a `sig-ops probe`
   Cloud Run job (new `sig-probe` job, same image pattern as `sig-ingest-muckrock`):
   - probe targets: the hosted `sig-api` (`/`, `/v1/coverage`), the public `sig-web`
     service, the `sig-public` export objects, and the Cloud SQL reachability check
     the probe already supports;
   - each sweep appended durably — **per-run timestamped objects under
     `gs://…-sig-restricted/ops/probes/<date>/<ts>.jsonl`** (the private bucket;
     probe output carries no secrets). Per-run objects, not read-modify-write, so the
     log stays WORM-shaped.
   - a `sig-ops probe-history` (or `probe --history`) read path that folds the stored
     objects into an uptime summary per target (count, latest state, last-N p95).
2. **Failure alerting.** A sweep containing a DOWN/degraded target POSTs through the
   existing `sig-alerts` receiver seam (`sig-ops alert`), so a real failure produces a
   real delivered alert — reusing P25.8's receiver, no new sink.
3. **Scheduled reingestion cadence.** Cloud Scheduler triggers on the existing
   ingest-job pattern for each **currently-fetchable** live source, cadence chosen per
   source's real update rhythm and recorded in a `ops/cadence.toml` (or equivalent):
   - `osm_overpass` — weekly (OSM changes continuously);
   - `muckrock` — monthly (already scheduled; verify, don't duplicate);
   - `decp_fr` (RAA index is weekly per sources.toml F9.18) — weekly;
   - `okcpd_policy` — monthly (manual revisions are rare);
   - the fetchable coarse/pathway sources (`carnegie`, `frwm`, `ccops_nyc_post`,
     `ccops_seattle`, `data_driven` sources already green) — monthly;
   - each scheduled run must leave the same honest fetch records a manual run leaves
     (refusals and link-rot are recorded, never retried into silence).
4. **Run-log.** Every scheduled execution appends a run row (source, mode, outcome,
   claims added, capture digests, refusal reason if any) under
   `gs://…-sig-restricted/ops/runs/` — the audit trail for "what ran when".
5. **Runbook + verification.** `docs/build/reports/GCP_DEPLOYMENT.md` (or a new ops
   doc) gains the schedule inventory: job names, cadences, where outputs land, how to
   pause/disable. `docs/build/runs/P26.1.md` records real evidence: the scheduler
   configs applied, at least one real scheduled (or manually-triggered scheduled-job)
   run's recorded output, and a probe-history summary built from real stored sweeps.

## Out of scope
- Flipping any source's `ingestion_permitted` (HG-03 stays human; only already-green
  sources get schedules).
- New connectors or sources (that is P26.2); public-surface/export rebuild cadence
  (the export is deterministic-by-commit — a live-informed refresh is a separate
  design question, noted here as follow-up).
- Alert delivery beyond the existing `sig-alerts` receiver (no email/PagerDuty).

## Acceptance criteria
- [ ] Cloud Scheduler + Cloud Run job exist for probes; a real sweep is durably stored and readable via the history path *(live-gated)*
- [ ] a forced-failure probe (e.g. a deliberately-bad target) produces a real `SIG-ALERT-RECEIVED` through `sig-alerts` *(live-gated)*
- [ ] every green live source has a recorded cadence + a scheduler trigger; at least one scheduled reingestion runs for real and leaves a run-log row + fetch records *(live-gated)*
- [ ] no refusal is retried into silence — scheduled runs record refusals exactly like manual ones *(deterministic)*
- [ ] `make check` + build-memory checks green; runbook updated; no secrets in files *(deterministic)*

## Cross-cutting invariants
Cited from `docs/tickets/00_MANIFEST.md § Cross-cutting invariants`: append-only
recording (ops logs are WORM-shaped per-run objects); honest refusal recording;
no secrets in files; the ingestion gate is never bypassed — schedules only drive
sources the gate already permits.
