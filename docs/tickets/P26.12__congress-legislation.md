## Goal
State legislation is live (P26.11). The federal layer is the same signal at the
highest tier — surveillance-relevant bills/resolutions in Congress (FISA
reauthorizations, facial-recognition moratoriums, drone authorities, ALPR
mandates). The Congress.gov API authenticates with the existing
`api.data.gov` key — this is a credential-free expansion.

## In scope — deliverables
1. **Source + connector path.** A `congress_gov` source row + connector (or a
   filed-into-accountability path matching the OpenStates shape): keyed
   `X-Api-Key` header per the P26.4 transport fix, bounded query windows,
   fixtures + tests.
2. **Keyword filtering.** Reuse the P26.11 surveillance-legislation vocab;
   federal-specific additions where needed (`foreign intelligence
   surveillance`, `fisa`, `section 702`, `geofence`, `stingray`,
   `cell-site simulator`, `data broker`). Matching bills/resolutions emit
   typed claims (title/status/chamber/latest action/matched keyword) with
   verbatim literals + document locators — never asserted as enacted law.
3. **Quota discipline.** api.data.gov enforces hourly/daily limits — the
   sweep plan is bounded per-window and rate-limit events are recorded
   honestly (the P26.11 quota lesson: refused probes still count — never
   re-probe a 429).
4. **Hosted run.** `sig-ingest-congress-gov` job + monthly scheduler; run
   rows + fetch records; spine delta measured; idempotent re-run proven.
5. **Records.** live_runs/ + GCS run rows; ladder re-measured; if a
   daily/hourly quota blocks the full sweep, the remainder lands as a
   DEFERRALS row naming the exact quota (the D-SOURCES.10-1 pattern).

## Out of scope
- Congress.gov member/vote/amendment depth (bill-level claims only this
  ticket); state legislation (P26.11); committee hearing records (a later
  class).
