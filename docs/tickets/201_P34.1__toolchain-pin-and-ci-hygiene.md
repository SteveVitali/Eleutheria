## In scope — deliverables

1. **Node.** `web/.nvmrc` holds an exact Node 24 LTS version chosen at ticket time from what `setup-node` resolves (Node 24 is the lowest line every engine in the lockfile admits — license-checker-rseidelsohn 5.0.1 needs node ≥ 24 / npm ≥ 11; H2 §3.5 item 1); `web/package.json` `"engines": {"node": ">=24 <25", "npm": ">=11 <12"}` and `"packageManager": "npm@11.<x>.<y>"`; `web/.npmrc` `engine-strict=true`; every `setup-node` step uses `node-version-file: web/.nvmrc` followed by an explicit install of the `packageManager` npm (or corepack, justified in the PR); job logs print `node -v` and `npm -v`. Fallback only by ADR: an exact Node 22 pin plus a license-checker whose engines admit 22 (SIG-ENG-046).
2. **Lockfile.** One regeneration under the pinned toolchain in this PR (blob sha recorded in the run ledger); a CI step `npm install --package-lock-only --ignore-scripts && git diff --exit-code web/package-lock.json` so any lockfile the pinned npm would write differently fails at PR time; later fixes are byte-identical cherry-picks or regenerations under the pin (H1 §2a).
3. **uv / Python.** `[tool.uv] required-version` pinned to the version CI uses (H2 names `==0.12.6`; verify at ticket time); `setup-uv` pinned to the same or reading the project setting; optionally `.python-version` to an exact patch.
4. **Runner and actions.** Confirm `runs-on: ubuntu-24.04` in every job of all five workflows (the seed PR pinned it unconditionally, S6R-27 — keep it); bump `actions/checkout`, `actions/setup-node`, `actions/upload-artifact` to the majors that target Node 24 (verify at ticket time). The Ubuntu 26 move is a later ticket.
5. **Pipefail.** Workflow-level `defaults: run: shell: bash` in all five workflows; a unit test asserts it per workflow and a mutation case in `tmp_path` shows `false | tee x` now fails the step.
6. **`main` runs complete (CF-01: this row owns them).** `cancel-in-progress: ${{ github.event_name == 'pull_request' }}`; the `docs` job also runs on `push` to `main`. `test_ci_docs_job_runs_only_on_pull_requests` is rewritten to the new policy in the same PR with ADR-151 — a policy change, not a relaxed living-record pin (OM-15 does not apply). SEED-02 wired the guards into the PR-triggered docs job only.
7. **`make ci-local`.** Runs the five jobs' commands locally (`SIG_REQUIRE_DB_TESTS=1` tests, docs-check, scans, composed e2e with web deps, web check + perf); a parity unit test maps every `run:` line in `ci.yml` to a target reachable from `ci-local`; `Makefile` lines 5–6 corrected.
8. **G3e test (B4).** CI's node major equals `.nvmrc`, and every devDependency `engines` range is satisfiable by the pinned node/npm.
9. **ADR-151 — Toolchain pin and CI truth** (this row is its author, plan §7): Node 24 LTS, uv pin, `ubuntu-24.04`; head-bound check-runs; flake allow-list with one re-run per head (B-15); CI-unavailable needs a verbatim, time-boxed operator waiver; tests assert invariants. - **Orchestrator side (for the record; not this worker's job).** It generates a nonce with `openssl rand -hex 16` and commits **only its sha256** in the boundary record — never to a file, an environment variable, git, the dispatch prompt or Devin's persistent Knowledge/memory; the dispatch prompt carries a separate **positive-control token**. - **Worker side — first, before any other work.** (1) Run `date -u` and write it as `Started:` in `docs/build/runs/P34.1.md` (it must be later than the dispatch record). (2) Report, in the first reply and in the run ledger's `## Isolation check` section, verbatim: the positive-control token from the dispatch prompt; the initial context sources (prompts, files, memories present at start); every 32-hex-character token held in context, or "none"; the `date -u` start; the harness/model `devin-desktop/swe-2-high/subagent`. Never search for the nonce, read orchestrator state or Devin Knowledge to find one, or guess.
- **Pass** = control token echoed, nonce absent, start and model recorded — judged by the orchestrator, recorded in its boundary record with the report kept verbatim.
- **On failure** the orchestrator pauses dispatch (`blockedOn: isolation check failed at P34.1`) and the fallback order of round 27 applies (SB-3, **"Approve headless fallback (Recommended)"**, 2026-10-01T13:46:58Z): (1) a verified non-interactive Devin command via `drive-build.sh --agent-cmd` — only if T6 verified such a command exists; (2) the manual tier, `drive-build.sh --print-prompt`, one new session per ticket, after `gh auth status` passes.
