## In scope — deliverables

1. **Policy file** `docs/build/tools/record_policy/living_records.toml` (*location: agent choice, beside the other record policies*): the living paths (LEDGER, BUILD_INDEX, DEFERRALS, COVERAGE_MATRIX, readouts, `reports/current/`, `reports/obligations/*.jsonl`, `docs/build/README.md`, …), the frozen artifacts tests may assert over (dated reports, a closed round's `PLAN.json`), and the registry of `living_record_invariant` escape hatches with their reasons. *(SIG-ENG-040)*
2. **AST lint** `tests/unit/test_no_living_record_pins.py` (in `make check`): a test that reads a living path from the repository root (not `tmp_path`) fails if it contains (1) a literal matching a CURRENT STATE `key: value`, (2) an assertion that a **named** obligation, requirement or readout has a specific status, (3) `len(<derived from a living record>) == <int literal>`, or (4) a literal row range or date ("rows 1-200"). Allowed: vocabulary membership, uniqueness, generated == source, reference resolution, append-only properties, frozen-artifact facts, and `@pytest.mark.living_record_invariant("<why>")` listed in the policy. It reports files and tests evaluated (> 0). *(SIG-ENG-040)*
3. **Convert or delete the remaining pins, each in its own commit, never relaxed (OM-15):** the three tests the validator flags `living-pin?` today and `test_repo_docs_current_state.py` (move its wording checks to the docs-freshness detector, or delete them); anything else the lint finds on first run. *(SIG-ENG-040)*
4. **Nightly advance backtest** (`nightly.yml`, read-only): run the real-tree tests from commit *C* against the tree at the next commit *C′* that legitimately changed a living record; a pin fails exactly at such a transition (B4 G6; the #165/#179/#185 shape). Its report names the test and the transition. *(SIG-ENG-040)*
5. **Convention note** in `tests/AGENTS.md`: read living control records only through the validators or a snapshot commit; a failing pin is converted or deleted, never relaxed.
