## Goal
Close the loop back to the commons for real: SIG-generated field-verification tasks appear as a MapRoulette challenge, human OSM edits made from those tasks flow back into the `LeverageLedger` via the changeset feed (hashtag-filtered), the Organised Editing activity is registered and disclosed, and the contributor onboarding is validated by the moderated usability study the spec requires.

## In scope — deliverables
1. **MapRoulette client** (`tasks/src/tasks/maproulette.py`): create/update a challenge from a `TaskPool` selection (geo tasks only; instructions cite SIG's evidence; hashtag `#sig-<jurisdiction>` per §35), fetch task status changes; `HttpxTransport` + `PoliteFetcher`; `sig-tasks maproulette push|pull --challenge …` behind `SIG_MAPROULETTE_API_KEY`; without the key: dry-run JSON of the payloads.
2. **OSM changeset feed** (`tasks/src/tasks/osm_feed.py`): poll the public changeset API filtered by the SIG hashtag (and optionally the OE page tag), attribute edits to `LeverageLedger` rows (append-only), never store OSM user names beyond the public changeset id (Part VIII); `sig-tasks osm-feed pull --since …`; replay tests over recorded fixtures (`tests/tasks/fixtures/osm_changesets_*.xml`).
3. **Organised Editing record:** `docs/governance/organised-editing-activity.md` gets the registration section (page URL placeholder → `SIG_OSM_OE_PAGE` when provided; contact channel = org address; disclosure of the account holder role); `tasks.contribution` `registered` flag reads from `ops/config.toml`; a test asserts pushing a challenge is refused while `registered=false` (SIG-CONTRIB conduct ids, RISK-P16-14).
4. **§7 metric page from real data:** the contribution-back metrics page (P16.2) reads `LeverageLedger` rows through `data.ts` `export` mode instead of fixtures.
5. **Usability study:** finalise `docs/governance/contributor-onboarding-usability-study.md` into a runnable protocol (tasks, consent text with no personal data retained, timing method, success criteria median ≤10 min, ≥5 naïve participants); instrument the L0 form with **opt-in, aggregate-only** timing (no per-user rows; a count + median stored via `ContributorRepo` as an aggregate record); `docs/build/USABILITY_STUDY.md` = protocol + results (or "not yet run — gate pending HG-10") + changes made to onboarding from findings.
6. **ADR-069** (MapRoulette + changeset feed design; ADR-055 amended), risk register (`RISK-P21-12` challenge instructions leak sensitive coordinates → tier filter before push; `RISK-P21-13` hashtag squatting → OE page + challenge id cross-check), traceability, `docs/build/CONTRIBUTION_BACK_LIVE.md` (runbook + what ran live).

## Out of scope (scope-creep guard — do NOT do these here)
- Automated OSM edits of any kind (spec forbids; human-mediated only). Creating accounts (HG-08). Running the study without participants (HG-10). New task detectors. Curation UI changes beyond the timing hook.
