## Notes for execution

- **The guard's scope is the ArcGIS shape, not a flat `owner` grep.** `"owner"` is also the obligation-event schema field (~762× in `docs/build/reports/obligations/events.jsonl`, plus frozen `memory-repair/` archives and report JSONs) — a global owner-field grep is red forever at its own head. The guard fails on: any hash-listed handle in tracked files; an `item_owner` key anywhere; and an `owner`/`item_owner` field inside the five named catalog/disposition files (or a declared path set of ArcGIS-sweep outputs).
- **`handle_crawl_check.py` already exists** (ADR-178, SIG-PUB-002) and scans the tip — but classifies `docs/build/{runs,pr,reports,planning}` + `docs/tickets/` as `RETAINED_PREFIXES` (hits counted, never failed) and is **not wired into CI** — exactly how 15085e0a's re-addition stayed green. The new guard closes that tension: fail-closed on handle-list entries in retained paths too (the retained-prefix reasoning applied to disclosure-time prose, not personal ids). Extend it or add a sibling check; wire it into a CI job.
