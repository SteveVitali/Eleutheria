## Goal

Make subject keys truthful and unique per real subject. CP-2's change: (a) the subject-key field set is **pinned per target kind** — the fields composing a subject key are declared per target (site, device, jurisdiction, actor, …) and versioned, never an incidental concat of whatever the emitter happened to have; (b) keys are **scoped by tenant/state** — a subject key carries its scope so two tenants' coincidentally-equal strings never collide into one subject; (c) the **5,278 collided subjects** (the plan row's count — distinct real subjects folded onto one key by the old derivation) are **re-keyed append-only**: a hosted run appends re-keying correction claims that split each collided key into its constituent subjects, and subsequent ingest mints under the pinned keys — no `UPDATE`, no `DELETE`, the old rows stay and the correction rows carry the new binding (the claim spine's correction model, not a rewrite). The re-key run is bounded, dry-runnable, and its before/after collision counts are recorded; the `/status/` notice discloses the dedup-behaviour change per S6 A-20.
