## Goal
Every hosted ingestion execution records when it finished and how. The public freshness surface then shows a real
last-successful-run date per source, and `not-recorded` appears only where no completed run exists.

## In scope — deliverables
1. **Per-execution run identity.** Each execution gets its own `ingest_run` row. Add an execution discriminator
   (for example the Cloud Run execution id, or a generated run id passed through `parameters`/`environment`) so
   `_ensure_run` no longer folds executions together. Replays and shadow runs stay distinguishable (`is_replay`,
   `shadow_mode`).
2. **Append-only completion.** Add a new sqitch change: an `ingest_run_completion` table (or equivalent) with
   `run_id`, `status` (ok / partial / quota_reached / failed), `finished_at`, counts, and the WORM run-row URI.
   Completion is **appended**. `ingest_run` is never updated. (ADR-R9-RUNLIFE decides and records this. The
   alternative, a narrowly scoped lifecycle update, is rejected unless the ADR argues it against the "no UPDATE
   path in `db/`" invariant.)
3. **Write completion** at the end of every pipeline execution: the success path, the quota stop and failure
   paths where the process survives, and the `store_run_row` seam. A SIGKILLed run records nothing and stays
   honestly "no completion".
4. **Backfill from WORM.** Build a one-shot, idempotent backfill that reads the committed GCS run rows and appends
   completion rows labelled `backfilled_from=<gs URI>`, mapping each run row to its `ingest_run` by
   source/connector/time. Ambiguous rows are recorded as unmatched, never guessed. Run it as a Cloud Run job (the
   `materialize.sh` pattern), then re-run it for +0.
5. **Shaping.** `last_successful_run` reads successful completion rows. `last_content_change` reads only completions
   that **inserted > 0 claims**, never any completion. `not-recorded` stays the explicit token where no such run exists.
6. **Keeping it live.** The completion writes only happen once the scheduled jobs run this code. The roll of all
   ingest jobs by pinned digest is owned by **P31.4**. Until then, freshness advances only through the backfill,
   and the run ledger says so.
7. **Verification.** A read-only hosted freshness shape (`exports shape --dsn …` or a freshness-only read)
   shows ISO dates for sources with a completed run. Optionally (Q3), run a national re-export + republish via
   `ops/gcp/export.sh` and the P30.3 publish path. It pauses if the published diff shows anything beyond freshness
   plus routine cadence data. Then `probe-hosted`.

## Out of scope
- Changing cadences or schedulers. Any change to claim writes (P31.3 owns the write path; this ticket touches only
  run identity and completion).
- Rewriting historical `ingest_run` rows (append-only; the backfill appends).

## Acceptance criteria
- [ ] Two executions of the same connector version produce two `ingest_run` rows, each with an appended completion (real-PG test) *(deterministic)*.
- [ ] The backfill appends completions for matched WORM run rows, records the unmatched ones, and re-runs +0 *(live)*.
- [ ] Hosted freshness shows ISO dates for sources with a completed run; `not-recorded` appears only where honest *(live)*.
- [ ] No `UPDATE` of `ingest_run` anywhere; ADR-R9-RUNLIFE with `## Revisit trigger` + Appendix F row; `make check` + `make test-db` green.
