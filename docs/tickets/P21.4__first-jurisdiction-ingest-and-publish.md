## In scope — deliverables
1. **Runtime composition** (`ops/`): `ops/docker-compose.yml` (PG18+PostGIS `postgis/postgis:18-3.6` with sqitch deploy on start; the API via `uvicorn`; a static server for `web/dist`) + `sig-ops up|down|status|seed --jurisdiction okc` commands; `ops/README.md` (one page). No cloud-specific config; SIG-STORE-003 zero-cost posture = runs on one small machine.
2. **Export-backed web data layer:** `web/src/lib/data.ts` chooses `SIG_DATA_SOURCE=fixtures|export` (default `fixtures` so CI is unchanged); in `export` mode reads the `sig-exports build` output directory (JSON/Parquet-derived JSON + PMTiles path) at build time. Every page that read a fixture reads through `data.ts`. Zero-JS budget unchanged (build-time only). e2e suite runs once in each mode in CI (`export` mode over an export built from the composed fixture DB — no network).
3. **The OKC run** (`docs/build/tools/run_okc.sh`, committed): `sig-ops up` → `sig-connectors run --source <id> --mode live --sink pg --dsn $SIG_STAGING_DSN` for each green OKC source (`--mode shadow` for the rest, recorded) → `sig-resolution match --dsn $SIG_STAGING_DSN --jurisdiction okc` (P19.4) → `python -m reconcile resolve --dsn $SIG_STAGING_DSN --jurisdiction okc` (P19.4) → `sig-db annotations rebuild --dsn $SIG_STAGING_DSN` (P21.2; skipped with a note in the shrunk case) → `sig-exports build --jurisdiction okc --out exports/out/okc` → `SIG_DATA_SOURCE=export npm --prefix web run build` → J-1 traversal + Q-1…Q-13 executed against the **running API** (`tests/acceptance` gets a `--live-api` option; results saved as `docs/build/okc/acceptance_<date>.json`).
4. **Staging deploy:** publish `web/dist` + the API to the staging target (default local compose); run `npm run test:e2e` and `lhci` against the staging URL; run the hostile-reader review checklist (`docs/governance/hostile-reader-review-dossier.md`) over the live OKC dossier and record the outcome.
5. **`docs/build/PUBLICATION_CHECKLIST.md`:** the pre-launch list with tick boxes and evidence links: legal home (HG-01), two-reviewer concurrence (HG-11, recorded through `ReviewerConcurrence` — a signed checklist file `docs/build/okc/concurrence.md` with roles + dates), takedown/corrections contacts live, ODbL disposition (HG-02) or link-only fallback active, sensitivity tier + coordinate rules verified on every published page (`policy.publication` test over the export), officer-naming gate green on the live data, robots/`/terms` served, licence statement per compartment on `/terms`, backups of PG + OCFL taken.
6. **`docs/build/FIRST_JURISDICTION_REPORT.md`:** what was fetched (from the fetch records), claim/evidence/contradiction/task counts, the J-1 output, the acceptance-query table, Lighthouse/axe results, what remained fixture-backed and why (per-source gate state), the retrospective delta vs `P06.1_retrospective.md` (what the live data changed), and the go/no-go state per gate.
7. **Go public** (only if all gates ticked): cut-over per `ops/README.md`; record URL + date in the report and in `CHANGELOG.md` (`0.2.0` "first public jurisdiction").
8. **ADR-066** (runtime composition + export-backed web data layer); risk register `RISK-P21-06` (live pages depend on export freshness → build timestamp on every page, SIG-UI as-of banner), `RISK-P21-07` (staging exposes real data before gates → staging is access-restricted or local); traceability.
