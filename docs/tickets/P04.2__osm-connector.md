## Goal
The first real connector on the framework: `osm` ingests physical assets from OpenStreetMap
(nodes/ways/relations), consuming the full surveillance-tag vocabulary, splitting semicolon
multi-values, and preserving element id **and version** — landing into a physically **separate
ODbL-licensed asset table** under the REFERENCE custody posture.

## In scope — deliverables
1. The `osm` connector on the P04.1 interface, handling **nodes, ways, relations**, splitting semicolon multi-values as unordered sets, normalizing across the surveillance keys — SIG-INGEST-045; a surveillance-bearing key outside the allowlist recorded as an unmapped value + research task.
2. **`(osm_type, osm_id, version)` keying** — a bare element id is not a stable reference — SIG-INGEST-045b/045f; element id and version preserved so a later OSM edit is detectable.
3. **`first_observed` walked from element history** (the version where surveillance tags first appeared), never the creation timestamp — SIG-INGEST-045a/045c.
4. **Deletion via snapshot diffing**, distinguishing *deleted from OSM* (a mapping event) from *removed from the street* (a world event) — SIG-INGEST-045g.
5. **OSM `user`/`uid` discarded at ingest** (targeting-surface hazard); `changeset` retained as provenance — SIG-INGEST-045e; Overpass quota/etiquette honored via the shared layer with a descriptive UA — SIG-INGEST-045d/045h/045i/045j.
6. Output lands in the **separate ODbL asset table** (REFERENCE posture) — SIG-ONTO-007, SIG-LIC-006; committed fixtures + a canary.
