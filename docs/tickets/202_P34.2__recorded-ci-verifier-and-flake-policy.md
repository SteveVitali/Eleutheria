## In scope — deliverables

1. **G3b recorded-CI verifier** in the CI `docs` job: for every Round-11 PHASE LOG `done` entry and run-ledger `ci:` line the PR adds (all of them in the nightly run), `gh api repos/{owner}/{repo}/actions/runs/{id}` must return a run whose `head_sha` equals the recorded sha and whose conclusion equals the recorded state; a `done` entry with no `ci:` field fails (SIG-MEM-007: "verifiable by CI against GitHub"). Tests use recorded API responses (no network).
2. **G3c external-state delta** inside `ci_boundary.py` (extends SEED-02b's G3a): `origin/main`'s sha; `git merge-base --is-ancestor origin/main <chainTip>`; PRs merged since the last boundary; open PRs whose head is no chain row — written into the `ci-boundary/1` record and the boundary line; an off-stack merge, or a chain PR retargeted or rebased outside the operator's documented procedure, sets `blockedOn` (OM-03, OM-17).
3. **`ci_flakes.toml`** (committed; each entry: check name, failure-signature regex, reason, expiry) and a re-run log: only a failure matching an unexpired entry gets one `gh run rerun --failed` per head; both attempts are recorded; never quarantine, skip, xfail or loosen to pass (H2 §4.4, CI-5; B-15).
4. **Lighthouse stabilisation:** `numberOfRuns: 3` with median aggregation, or the score assertion moved to nightly with per-PR byte budgets kept — an ADR decides; ADR-134's budgets unchanged.
5. **PY-SUBSTR-1 fix:** the substring assertion `'8.5' not in str(row)` (`tests/api/test_curation_onboarding_timing.py:55`, F-316 — re-locate at ticket time) asserts on fields, not on `str(row)`.
6. **npm advisory gate:** `npm audit --omit=dev --audit-level=high` per PR, or nightly with an allow-list file carrying expiry; the level is decided in the ticket and recorded in the ADR or PR.
7. **Non-vacuous leak check:** the `security` job's leak check fails when `SIG_GCP_PROJECT` is unset (unless the operator sets it, OP-07 / H2 §5 S-4) and reports candidates/evaluated (SIG-ENG-042).
