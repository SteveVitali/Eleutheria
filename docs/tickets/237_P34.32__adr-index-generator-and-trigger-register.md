## In scope — deliverables

1. **Generator patch (G8-1; local, vendored `scripts/docs/adr-index.sh`):** parses `# ADR-NNN: <title>`, `# ADR-NNN — <title>` and the other header forms in use; owning phase from `**Ticket:**`, then `**Phase:**`, then `**Phase / ticket:**`; status from the header **and** the latest appended `## Status updates` line (Superseded / Amended / Qualified / Extended / Revisited by ADR-NNN); optionally a "date corrected → ADR-146" marker derived from `date_corrections.csv` (ADR-146 D2, CF-02). `docs/adr/README.md` regenerated, never hand-edited. The patch is recorded for the upstream skill proposal (B6), not sent from here. *(SIG-ENG-039)*
2. **Index check:** every index row has a title, an owning ticket or phase and a status — 0 rows reading "—" (B4 NEW-6: 79/142/25 failures before); ADR-146+ must use the template header fields (hard failure). The validator's ADR-index warning becomes a failure once the tree passes. *(SIG-ENG-039)*
3. **Supersession / qualification check (G8-2, COV-14):** an ADR named in any later ADR's `**Supersedes:**`, `**Amends:**`, `**Qualifies:**` or `**Extends:**` field carries the matching appended `- **Status:** <kind> by ADR-NNN (<date -u>)` line in a `## Status updates` section (the only legal body change, guard form). The ones still missing at dispatch (F3 NEW-4 named ADR-015, 058 §3, 075, 092, 096 §1; SEED-11d appended many) are appended here with `date -u`; ticket-authored ADRs keep appending their own (S6R-24). *(SIG-ENG-039)*
4. **Trigger-register checker (G8-3) over `ADR_TRIGGERS.csv`:** exactly one row per revisit trigger (every ADR's `## Revisit trigger`); `trigger_sha256` = sha256 of the trigger text **up to the first `### Trigger evaluation`** (CARRY: SEED-11d → SEED-15), so an appended evaluation does not change it but an edited trigger is visible; `state` ∈ {quiet, fired-unanswered, fired-answered(ref), superseded(ref), dormant(reason)}; refs resolve to an ADR file or a chain row; `home` is an **open** BL row unless quiet or superseded; `last_evaluated` is a `date -u` value. A `--round-tail <round-start>` mode fails when any row's `last_evaluated` predates the round or a `fired-unanswered` row has no S1 disposition (used by P34.33 and the P38 tail). A `probe_id` column is honoured when present (G10 hook). *(SIG-ENG-043)*
5. **CI:** both checks join `make docs-check` (and so the CI `docs` job); each reports items offered and evaluated (SIG-ENG-042 shape).
