# P26.7 — State DOT / 511 traffic-camera feeds: a new source class (P26)

- **Semantic id:** `SOURCES.7` · **Phase:** 26 · **Kind:** ticket · **Tag:** p26-sources
- **base_branch:** `devin/p26-6-agenda-content-claims` · **Depends on:** P26.5/P26.6 (the tenant + document-depth machinery); GL-GATE-06 + ADR-087 in force
- **Run:** `implement-spec spec=docs/tickets/P26.7__dot-511-camera-feeds.md live_verification=true`
- **Gate status:** engineering — GL-GATE-06 covers resolved-clear public terms; each host's robots decides; rights packets for anything ambiguous.
- **Live stage:** real per-state fetches; every outcome recorded.

## Goal
Most US states publish their traffic-camera inventory through 511 traveler-info
systems — public JSON/API endpoints listing camera locations, roadways, and
jurisdictions. This is **literally a government-published surveillance
infrastructure registry** — the highest-signal physical-layer source SIG has not
yet tapped, and a natural complement to the OSM `man_made=surveillance` layer
(which is crowdsourced; DOT feeds are authoritative-operator-published).

## In scope — deliverables
1. **Discovery sweep.** Enumerate the state 511/DOT camera endpoints: the common
   platforms are ArcGIS-hosted feature services (`arcgis.com`/`arcg.is` REST
   layers — many states publish camera layers there), per-state 511 APIs
   (e.g. `511ga.org`, `511.org`, `511ny.org`, `fl511.com`, `i81`, `ohgo`,
   `511texas`, `modot`, `wsdot`, `az511`, …), and state DOT open-data portals.
   Record the enumeration source per host — vendor-published lists, ArcGIS hub
   discovery, state open-data catalogs.
2. **Connector.** A `dot_511` (or `traffic_cameras`) connector on the established
   pattern: per-state target rows in `live_targets.toml` (or a tenant-style
   registry if hosts multiply the same way agenda platforms did), fixture-backed
   parse, claims carrying camera location/roadway/jurisdiction with evidence +
   locator. Camera rows are *infrastructure* claims — no person data exists in
   these feeds by construction.
3. **Sensitivity check.** DOT camera coordinates are operator-published public
   data — but verify each feed's granularity against `policy.sensitivity` before
   emitting; jurisdiction/precision rules still apply at claim time.
4. **Rights.** Each feed's terms resolved against GL-GATE-06 (most are public
   government data / open-API terms); unresolved terms stay gated with the
   blocker named. robots honored per host — ArcGIS REST and most 511 hosts are
   permissive; any `Disallow` is recorded, not bypassed.
5. **Cadence + records.** Yielding states get monthly cadence rows; per-state
   outcomes in `live_runs/` + GCS run-log; the ladder re-measured.

## Out of scope
- Live video/image capture (we ingest the camera *registry*, never the feed
  content — Part VIII); non-DOT camera sources (private networks need their own
  rights review); flipping unresolved terms.

## Acceptance criteria
- [ ] a sourced enumeration of state 511/DOT camera endpoints lands as target rows — ≥10 states attempted *(deterministic + live-gated)*
- [ ] ≥1 state's feed produces real camera-location claims with evidence+locators into the hosted spine *(live-gated)*
- [ ] per-host robots honored; every outcome recorded; sensitivity rules verified against emitted coordinates *(deterministic)*
- [ ] yielding states get cadence rows; `sig-ops cadence --check` green; ladder re-measured *(deterministic)*
- [ ] `make check` + `check-build-memory` + `check_backlog` green *(deterministic)*
