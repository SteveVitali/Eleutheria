## In scope — deliverables
1. **Camera-count reconciliation**: the six count predicates (`contracted_/invoiced_/installed_/active_/mapped_/claimed_device_count`) held distinct; Phase 2.3 refuses to compare mismatched `count_basis`, emitting `PREDICATE_CONFLATION`; `mapped_device_count` is a lower bound; output carries every predicate + `unresolved_delta`, never one "true count" — SIG-RECON-026/027/028/029.
2. **Device attribution**: candidate generation from spatial/road-network/adjacency/vendor signals; output an **L4 `probable` inference**, never written to `operator` as observed, never auto-pushed to OSM; the hard cases modelled, not defaulted — SIG-RECON-030/031/032/033.
3. **Sharing-edge reconciliation**: the three edge types reconciled separately; **asymmetry emits `SHARING_ASYMMETRY` and a research task — a finding, not a merge**; single-snapshot edges carry `valid_from_kind='unknown'`; `observed_use` ↛ `configured_access` at L1 — SIG-RECON-034/035/036/037.
4. **Deployment lifecycle**: the four tracks resolved independently; event-log transitions preferred; fuzzy dates ordered by EDTF envelope (else *unordered-within-window*); the **vendor-replacement pattern rendered as "vendor replaced," never "surveillance removed"**; canceled-contract-with-hardware-present stated plainly — SIG-RECON-038/039/040/041/042.
5. **Retention** (three predicates; vendor defaults never populate configuration) — SIG-RECON-043.
6. **Policy-versus-configuration** divergence surfaced as a first-class finding with both sides' evidence, never editorially collapsed — SIG-RECON-044.
7. **Snapshot-diff** at the extracted-field level, per-field change events with both values and dates — SIG-RECON-045.
