## Goal

Land the live half of PKG-07: an append-only backfill that writes the `technology` claim P35.15a's emit path now produces onto the ~200k existing camera-registry subjects that predate it (F-523 measured ~232,628 subjects emitted `record_kind="traffic_camera"` with no technology; ~77.4% are ALPR/police-CCTV/enforcement by their own registry target). Each backfilled subject gains an INSERT-only `technology` claim whose value is its target's declared registry slug — never a substring inference (NEW-7/FM-05) — with `claim_evidence` links citing the subject's existing evidence captures and a provenance mark that identifies the claim as backfill-derived. A second run appends `+0`. After it, the catalog acceptance holds on the live spine: Flock/DeFlock-sourced records read ALPR and no record reads `traffic_camera` unless its target literally declares it.

## In scope (deliverables)

1. **The backfill command.** Dry-run by default: emits the full per-target/per-slug plan and counts without writing; `--apply` writes. INSERT-only; chunked commits (the `SIG_COMMIT_CHUNK_SIZE` precedent); resumable — an interrupted run resumes and still finishes `+0`-convergent; one run record with its report, so the backfill is auditable as a run, not invisible batch SQL.
2. **Claim shape.** Each written claim is an ordinary `sig.assertion/1` row: subject = the existing registry subject, predicate = `technology`, value = the target's declared slug, `claim_evidence` links to the subject's existing evidence captures, and a provenance/basis mark identifies it as produced by this backfill run (derived claims are labelled, never passed off as connector-fresh). No claim is written without an evidence link; no subject gains a slug its target does not declare.
3. **Coverage of the defect classes.** Flock/DeFlock-lineage subjects get the ALPR family slugs their targets declare; targets that genuinely are traffic cameras keep `traffic_camera`; a subject whose target declares nothing is left untouched and counted in the report (never a guessed slug — SIG-ONTO-021, coarsest level the evidence supports).
4. **Dry-run report as evidence.** The dry-run's per-target counts and the `--apply` pre/post counts land in the run ledger; the live counts are compared with F-523's expectation (~77.4% of ~232,628 subjects moving off untyped/`traffic_camera`) and any large divergence is recorded, not smoothed.
5. **Fixture + DB tests.** A seeded fixture spine with pre-PKG-07-shaped claims gains the declared `technology` claims; a second run writes `+0`; a subject with no declared slug gains nothing; every written claim has ≥ 1 `claim_evidence` link; `n_tup_upd`/`n_tup_del` stay 0 on the touched tables (`SIG_REQUIRE_DB_TESTS` for the PG-side assertions).
6. **Requirement stamps** in the PR body: F-329, F-523 (as owned findings) + the cited ids above.
