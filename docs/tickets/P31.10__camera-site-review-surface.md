## Goal
A vetted curator **can** work through a stratified sample of camera-site proposals with the evidence side by side
(the Round-10 campaign will). Each accept/reject is written as an append-only PG `review_decision`, with the
pseudonymous curator id, through the existing `PgReviewQueue.decide`; "unsure" writes no decision (the item stays
pending — see In scope 1).

## In scope — deliverables
1. **PG-backed queue.** When the curation app has a DSN, `/review-queue` reads PG `review_item` (filterable by prefix
   `er_match:camera_site:` / `er_match:camera_site_disputed:`, tier, and bucket — the P31.3
   `er_match:identity_duplicate:*` family is excluded from the camera-site queue), and `decide` writes through
   `PgReviewQueue.decide` with `decided_by` = the pseudonymous curator id from the tier token. The demo seed remains
   the no-DSN default for tests. The schema allows only `accept`/`reject`: an "unsure"/defer in the UI writes **no**
   `review_decision` (the item stays pending). Persisting "unsure" would need a new sqitch change + ADR — out of scope
   unless the implementer finds it necessary, and never an in-place edit.
2. **Evidence view.** For each pair: both observations (source, coordinates at the curator's tier, external refs,
   operator, description), the distance, the matcher tier and score, and any soft conflict. There are no raw person
   data. Coordinate reduction follows §19.4 for the curator tier.
3. **Campaign sampler.** A CLI (`sig-resolution review sample --dsn … --strata … --n …`) that draws a **stratified,
   seeded, reproducible** sample across tiers 1g/3g/4g/5g plus the soft-conflict and disputed buckets, and marks it as
   a campaign (append-only). Auto-write tiers are included on purpose so humans audit them. Sizes are CLI
   parameters; the default is the design §6 Q11 proposal (~400 stratified pairs) as the **Round-10** campaign design.
   A campaign may be materialized on hosted and labelled as prepared for Round 10; nobody labels it in Round 9.
4. **Offline path.** `review export` / `review import` for JSONL labelling sessions, writing the same append-only decisions.
5. **Tests:** decide → a PG `review_decision` row with the curator id; the demo path is unchanged without a DSN; the sampler
   is reproducible for a seed; zero-JS public pages are unaffected; the `/curate/**` island stays within ADR-068.
