# P27.10 — Custom-domain cut-over to surveillancegraph.org (P27)

- **Semantic id:** `LAUNCH.10` · **Phase:** 27 · **Kind:** ticket · **Tag:** p27-launch
- **base_branch:** `devin/p27-9-interactive-islands` · **Depends on:** P27.8 (public cut-over + deploy sync), P27.6 (canonical `site`/metadata), P27.9 (chain tip)
- **Run:** `implement-spec spec=docs/tickets/P27.10__domain-cutover-surveillancegraph.md live_verification=true`
- **Gate status:** **HG-11 / Go-public** — the ticket does everything up to the cut-over and stages the exact DNS records; **adding the Squarespace DNS records + confirming the domain is the operator's action** (a live human decision, never auto-ticked). A RETURN PASS row holds until the operator confirms.

## Goal
Make **`https://surveillancegraph.org`** the canonical public origin for the production public surface —
Google-managed TLS, `www`→apex — pointing at the deployed `sig-web` Cloud Run service (project
`zeta-medley-508121-u7`, region `us-central1`), replacing the `*.run.app` URL so that permalinks,
citations and the published site all resolve to the real domain, with no canonical-URL churn after launch.
The domain is **public config, never a secret**.

## In scope — deliverables
1. **(a) Domain mapping + TLS.** Wire `surveillancegraph.org` (+ `www`→apex) to the `sig-web` Cloud Run
   service with **Google-managed TLS**, via **either** a Cloud Run domain mapping **or** an external
   HTTPS load balancer + serverless NEG — implementer's choice, justified in an **ADR** (the next free
   ADR number; **home it under `BL-056`**, add its Appendix F row to
   `docs/research/_meta/spec_src/99a_appF_adr.md` and run `sh docs/research/_meta/spec_src/BUILD.sh`;
   every ADR carries a `## Revisit trigger`, SIG-STORE-007). Land the mapping as idempotent
   IaC/scripts under `ops/gcp/` (dry-run-checkable without ADC, like the existing provision/backup
   scripts), not a one-off console action.
2. **(b) Exact Squarespace DNS records for the operator.** Produce the precise records the operator must
   add at Squarespace (registrar + DNS): the **GCP domain-verification `TXT`** + the **apex `A`/`AAAA`**
   records (the apex cannot `CNAME`) for a Cloud Run domain mapping, **or** the **static-IP `A`** record
   (apex) + `www` `CNAME` for the LB path — matching whichever (a) chose. Record them as the concrete
   **HG-11 / Go-public gate action** (a RETURN PASS row + the publication checklist), copy-pasteable,
   with the expected values from the realized GCP resources.
3. **(c) Canonical origin.** Set `web/astro.config.mjs` `site = "https://surveillancegraph.org"` so
   permalinks, citations and sitemaps resolve to the real domain (superseding the run.app origin P27.6
   set). Confirm the belief-pinned permalink/citation (SIG-UI-035) uses it.
4. **(d) Probe targets.** Point `ops/gcp/config.sh` + `ops/cadence.toml` probe/uptime URLs at the custom
   domain (keep the run.app URL as a documented fallback where sensible), so `probe-hosted` and the
   cadence sweeps watch the canonical origin.
5. **(e) Verification.** Once the operator has added the DNS records: confirm **valid Google-managed
   TLS** on `https://surveillancegraph.org` (+ `www`→apex redirect), the **real national data** renders
   at the domain (not the demo), and `sig-ops probe-hosted` is green against the custom domain. Record
   the served spine/export watermark.
6. **Records:** `docs/build/runs/P27.10.md`, PR body, `PUBLICATION_CHECKLIST` update, the RETURN PASS row
   for the gated DNS cut-over until the operator confirms.
