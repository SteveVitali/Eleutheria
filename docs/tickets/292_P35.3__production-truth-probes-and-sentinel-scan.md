## Goal

Make production truth **checkable and cited**. Two halves, one contract: (a) every production-truth probe declares where it fires — pull request, release candidate, publish, schedule, or round tail — and writes the shared `sig.probe-run/1` record (id, `date -u`, result, output digest), so a probe's evidence is an artifact, not a claim; (b) the fixture-sentinel scan sweeps release candidates, the public web build and sampled live API responses for fixture/placeholder markers, and the live-claim binding forces every committed statement that asserts production state to cite a probe-run record ≤ 24 h old at its commit. A sentinel hit outside a declared fixture compartment fails the gate; a live-state claim without a citation fails the check.

## In scope (deliverables)

1. **Probe registry + trigger-point declarations** — every production-truth probe in the G10 matrix (route allow-list/absence, release record + page stamp, live-config drift, monitoring liveness, attribution sanity, jurisdiction–coordinate consistency, API-vs-release parity, number truth, the sentinel scan itself, the claim-marker check) is registered with its declared trigger points and `sig.probe-run/1` output; the registry validates that every entry declares ≥ 1 trigger point and names its owner row.
2. **The shared `probe-run/1` writer seam** — the existing republish-probe writer is reused (or factored into a shared helper, additive); every registered probe emits id + `date -u` + result + output sha256. A scheduled run that evaluated 0 of a non-empty candidate set fails (SIG-ENG-042 applied to probes).
3. **Fixture-sentinel scan (SIG-OPS-012)** — scans: (a) the release-candidate build output, (b) the public web build (`web/dist`), (c) a sampled live API response set. Sentinels: `example.test`, `sig.example`, `_FIXTURE`, `demo_`, `Reviewer A/B`, loopback URLs (`127.0.0.1`/`localhost` in a production context), `capture_kind: stand-in` without disclosure, and unregistered contact domains (`sig-project.org` et al.). A hit outside a declared fixture compartment fails the gate at that trigger point.
4. **Live-claim binding (SIG-MEM-011)** — a docs-check tool: a committed build-memory/readiness/README statement asserting production state must cite a `probe-run/1` record (id, time, result, output digest) no older than 24 h at its commit, the record resolvable under `docs/build/reports/probes/` or at a cited digested path. Its own limit is documented: it verifies the citation, not the truth.
5. **Claim-marker check (DR-C3-03)** — "human-verified" / "Reviewed" / "independent review" markers in build output or committed records require a recorded human-completion marker; absent → fail. No agent label counts as a human label (Round-11 truth rules).
6. **Wiring at the declared trigger points** — repo-side: the scan runs as a build-output/CI check (PR + candidate); scheduled and post-publish executions are declared in the registry and land as the owning rows' job legs (P34.44b's nightly job carries the scheduled API-sample leg; the publish rows carry post-publish); the tail sweep consumes the registry (ADR-199's contract is the binding shape).
7. **Tests** — planted `sig.example` IRI / `demo_` marker / loopback URL in fixture build output → fail; a live-state claim without a citation → fail, with one → pass; a probe entry without trigger points → registry validation fails; a 0-evaluated probe run → fail.
8. Requirement stamps in the PR body: `SIG-MEM-011`, `SIG-OPS-011`, `SIG-OPS-012`.
