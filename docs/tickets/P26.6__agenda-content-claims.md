# P26.6 — Agenda content depth: index records → typed claims (P26)

- **Semantic id:** `SOURCES.6` · **Phase:** 26 · **Kind:** ticket · **Tag:** p26-sources
- **base_branch:** `devin/p26-5-vendor-tenant-universe` · **Depends on:** P26.5 (the 665-capture tenant universe + per-platform index connectors)
- **Run:** `implement-spec spec=docs/tickets/P26.6__agenda-content-claims.md live_verification=true`
- **Gate status:** engineering — no human gate. New vocab is reviewed-as-data; robots still decides per host.
- **Live stage:** real bounded fetches of agenda/matter documents; per-tenant outcomes recorded.

## Goal
The agenda-platform connectors currently emit **index-level** records — meetings,
matters, and contract-family matters via `contract_matter_patterns`. The captured
indexes name real documents: agenda PDFs/HTML, minutes, matter detail pages. The
depth step turns index rows into **typed claims**: surveillance-relevant matters
(ALPR/drone/RTCC/Flock procurements, CCOPS ordinances, policy approvals) become real
typed claims with document locators — not just "a meeting happened".

## In scope — deliverables
1. **Document fetch path.** For each agenda-platform tenant that yielded an index
   capture, fetch the linked agenda/minutes/matter documents — **bounded**: a
   reviewed recency window (e.g. last N matters / last M months per tenant) so a
   tenant sweep stays bounded and idempotent. Documents capture to OCFL exactly
   like every other fetch.
2. **Surveillance-relevance extraction.** A reviewed keyword/type vocabulary
   (`agenda_content_vocab.toml` or extend the existing platform vocab) matching
   the surveillance domain: `alpr|automated license plate|flock|vigilant|rtcc|
   real.time crime|drone|uas|shotspotter|soundthinking|surveillance ordinance|
   ccops|facial recognition|body.?worn|cctv|license plate reader` plus
   procurement-matter types already in `contract_matter_patterns`. A document
   whose text matches emits typed claims (`procurement_notice` / matter-kind
   claims per the platform's claim shapes) with the **document locator**, never
   an inferred claim — the literal stays `raw_value`, verified against captured
   text exactly as the OKC document path does.
3. **Fail-closed on drift.** A document that doesn't parse as the platform's
   genre records `ContentDrift`; an empty/blocked document records honestly —
   never a fabricated extraction. Bounded window parameters live in the target
   row as data.
4. **Scale discipline.** Start with the tenants whose index captures are already
   committed (the 665-capture universe), but a bounded per-tenant cap (e.g. 20
   most-relevant documents per tenant per run) keeps a run finite — recorded as
   the coverage policy in the run ledger. Idempotent re-run proven.
5. **Records.** Per-tenant/per-document outcomes in `live_runs/` + the GCS
   run-log; the claim-count delta measured before/after on the hosted spine.

## Out of scope
- New source classes or new platforms (tenant universe is P26.5's).
- Extracting non-surveillance agenda content — the vocab is surveillance-scoped
  by design; a full civic-agenda corpus is a separate decision.
- Flipping unresolved sources; bypassing any robots disallow.

## Acceptance criteria
- [ ] agenda/matter documents fetch + capture for ≥1 tenant per platform with reviewed-window bounds *(live-gated)*
- [ ] surveillance-relevant documents emit typed claims with document locators + verbatim `raw_value`s; nothing asserted beyond captured text *(deterministic + live-gated)*
- [ ] drift/empty documents record honestly; bounded-window + idempotent re-run proven *(deterministic + live-gated)*
- [ ] fixtures + tests for each platform's document-parse path; `make check` + build-memory green *(deterministic)*
- [ ] claim-count delta on the hosted spine recorded in the run ledger *(live-gated)*
