## In scope — deliverables

1. **Link depth (C4 NEW-1, F-151).** Fix the relative-link depth in `release_pages.py` (`:117` evidence links, `:193` record links; every page template) so browse, evidence and entity links resolve from every route depth.
2. **Link-resolution crawl gate (DR-C4-01, agent draft).** `validate_release` crawls the staged tree: every same-origin `href`/`action` resolves to a file, or to an explicitly denied route (410 under P34.41's barrier); a broken link fails validation with the page and target named. Unit-tested on a fixture tree with a planted broken link.
3. **Page chrome (C4 NEW-5, NEW-22; F-155; DR-C4-02 agent draft).** Every exports-rendered page (record, browse, jurisdiction, compartment, evidence, dossier, landing, index, stub, tombstone, error) carries site navigation, a link to the corrections/dispute page P34.17 publishes (its text is P34.17's, never written here; SIG-UI-033) and the licence of the compartment it shows (SIG-LIC-011).
4. **Edge type (C4 NEW-6, F-156; SIG-UI-024).** Archive records and the published-record JSON carry the access-edge type — configured / observed / declared — instead of an untyped `sharing_access`; an additive JSON field with today's value kept readable (back-compat).
5. **Released dossiers (C4 NEW-7, F-157).** Released dossier pages state the provisional, evaluation-deferred posture ("no human check performed" — ADR-152; never "reviewed") and the release landing links them.
6. **Zero-record landing (C4 NEW-31).** A release with 0 records explains why on its landing instead of rendering an empty page.
7. **Honest absences (F5 PKG-03a).** `run_spine_export` emits `web/leverage.json` (the zeroed metric with its basis), **or** `data.ts` renders its absence as "not available" instead of throwing in export mode — the ticket picks one and records why; the map's empty-tiles case says that no tiles exist for the release rather than showing a silent empty basemap.
