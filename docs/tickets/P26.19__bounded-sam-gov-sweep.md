# P26.19 — Bounded SAM.gov sweep (fit one daily quota window) (P26)

- **Semantic id:** `SOURCES.18` · **Phase:** 26 · **Kind:** ticket · **Tag:** p26-sources
- **base_branch:** `devin/p26-18-chunked-commit` · **Depends on:** P26.14 (the widened sweep) + P26.4 (the keyed transport); D-FEDERAL.1-1
- **Run:** `implement-spec spec=docs/tickets/P26.19__bounded-sam-gov-sweep.md live_verification=true`
- **Gate status:** engineering — a sweep-width/scheduling change; the key already exists (`sig-sam-gov-key`). No new credential.
- **Live stage:** land the bounded sweep's `procurement_notice` claims into the hosted spine on one quota window.

## Problem (measured)
The P26.14 widened SAM.gov sweep over the full surveillance keyword set issues
more requests than the api.data.gov daily quota (250/day-class) allows.
Executions `lz4rx` (3600s) and `5z456` (14400s) were SIGKILLed fighting
persistent 429 back-offs; the Monday `sig-sched-sam-gov` cron (`k5bbv`,
2026-09-21) also failed. Because refused requests still count against the daily
counter, each failed run's retries re-consume the fresh window, so the next
run starts already-throttled. `sam_gov` remains at its original 7 claims
(the P26.4 bounded slice). D-FEDERAL.1-1 is OPEN with this evidence.

## In scope — deliverables
1. **Bound the sweep to the quota.** Rework the SAM.gov query plan so ONE run
   fits comfortably inside a single daily window (leave headroom — the run
   must not itself exhaust the quota). Options the connector should support,
   pick per measured request-cost: narrower/prioritised keyword set per run,
   a date-window (recent notices only), and/or a paged cursor that advances a
   little each day (persisted offset) so successive daily crons page the full
   space over time WITHOUT any single run exceeding quota.
2. **Quota-aware stop.** The sweep must stop cleanly and record an honest
   `rate_limit`/`quota_reached` outcome BEFORE hitting the hard 429 wall where
   possible (track request count against a configured budget), so a run never
   burns the window into a failure. Never re-probe after a 429 (the recorded
   lesson).
3. **Scheduling.** Confirm/adjust the `sig-sched-sam-gov` cron so it fires on a
   fresh window (well after the documented daily reset) and, if using the
   paged-cursor approach, advances coverage across days.
4. **Hosted proof.** Run the bounded sweep for real on a fresh window; land its
   `procurement_notice` claims; record the spine delta and per-run request
   count; prove an idempotent re-run (+0 on unchanged notices).
5. **Records.** `docs/build/runs/P26.19.md`, PR body, BUILD_INDEX row 116,
   LEDGER phase log; **close D-FEDERAL.1-1** (or narrow it to the paged-coverage
   tail if full coverage spans multiple days by design); ladder re-measured.

## Out of scope
- A key-tier upgrade (an operator/HG-09 action — note it in the run doc as the
  alternative that would let the full sweep run as-is); USAspending (already
  live, P26.14); changing the `procurement_notice` claim shape.

## Acceptance criteria
- [ ] the SAM.gov sweep is bounded so one run fits a single daily quota window with headroom; a request-budget stop records `quota_reached` honestly, never a 429-timeout crash *(deterministic — fixture/unit)*
- [ ] a bounded sweep runs live on a fresh window → `procurement_notice` claims into the hosted spine; per-run request count + spine delta recorded; idempotent re-run +0 *(live-gated)*
- [ ] D-FEDERAL.1-1 closed or narrowed to a by-design paged-coverage tail; `make check` + build-memory green; ladder re-measured *(deterministic)*
