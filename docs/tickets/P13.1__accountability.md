# P13.1 — Accountability events and the accountability connector

- **Sequence:** 31 of 46
- **Phase:** 13 — Accountability, policy, legal instruments
- **base_branch:** current checkout — the branch the previous ticket left checked out (stacked PR chain); `main` for P00.1
- **Depends on (must land earlier in the stack):** P12.2 (predecessor), P04.1 (connector framework), P01.1 (ontology defines the entities and the `epistemic_status` vocabulary)
- **Run:** `implement-spec spec=docs/tickets/P13.1__accountability.md`

## Goal
Bring accountability into the graph as first-class, epistemically-honest records: the
`AccountabilityEvent` and `LegalProceeding` entities, the `accountability` connector (Accountability
Atlas, Abuse Library, CourtListener), a required `epistemic_status` preserved end to end so an
allegation never renders with a factual verb, and incident-to-source links across all six source
classes with the class recorded.

## Load
- `docs/2_canonical_design_spec.md` §§ 11.17–11.18 (AccountabilityEvent / LegalProceeding), 23.8 (`accountability` connector), 13.3 (evidence and epistemics vocabularies).
- Part 0, Part I §3 (invariants), Appendix E glossary.

## In scope — deliverables
1. **`AccountabilityEvent`** and **`LegalProceeding`** as identity-only entities with their §11.17–11.18 predicate surfaces (event_type; `epistemic_status` REQUIRED; docket/posture/parties) — SIG-ONTO-038.
2. **`epistemic_status` required and preserved end to end**: rejected if absent on write, carried verbatim from the upstream where provided, and never flattened to "X happened" — SIG-ONTO-038.
3. **Six-source-class linkage**: an incident is linkable to all six OL-2E-AL-03 classes (primary record; court record; agency statement; vendor statement; investigative article; advocacy analysis), with the class **recorded** on the evidence link so a claim resting only on advocacy analysis is distinguishable from one resting on a court record — SIG-ONTO-039.
4. **The `accountability` connector** consuming the Accountability Atlas's five artifacts (issue-record CSV, source-index CSV, GeoJSON, data dictionary, research archive), the Abuse Library, and CourtListener as **targeted-lookup only** (§22.2); writes `AccountabilityEvent`, `LegalProceeding`, and source-class-tagged evidence links; crosswalks the upstream record categories rather than adopting them wholesale — §23.8.

## Out of scope (scope-creep guard — do NOT do these here)
- `Policy`, `LegalInstrument`, and policy/configuration divergence — P13.2.
- The general curated-source-index-without-normalization capability (§10.9, SIG-EPIS-030) — P13.2 owns it; this connector only consumes it.
- Public API / export surfaces over these entities — P14.1 / P14.2.

## Acceptance criteria (testable; from the Phase 13 Part X ACs, sub-set to this ticket)
- [ ] `epistemic_status` is **required and preserved end to end** — a write without it is rejected, and the ingested value survives ingestion → resolution → read unchanged. *(deterministic)*
- [ ] **An allegation never renders with a factual verb** — a surface/render test asserts an `alleged`/`disputed`/`retracted` event is never phrased as a confirmed fact. *(agentic)*
- [ ] **Incidents link to all six source classes with the class recorded** — a test builds an incident with all six OL-2E-AL-03 classes and asserts each link carries its class, and that an advocacy-only claim is distinguishable from a court-record claim. *(deterministic)*
