## In scope — deliverables

1. **Identities as code.** A committed, dry-run-by-default script (declared bindings in one reviewed file) that creates `sig-api-rt` (`roles/cloudsql.client`; accessor on `sig-pg-password` only), `sig-web-rt` (`roles/storage.objectViewer` on the web bucket only) and `sig-alerts-rt` (no project roles), and whose `--verify` diffs the live IAM against the declaration (read-only; reused by P35.1a's live-diff).
2. **Per-consumer secret accessors.** Each secret's IAM policy grants accessor only to its consumers' SAs (G1 §3.9: 11 secrets; `sig-api-env` has 0 versions — record it, do not delete it here); the default compute SA keeps its accessor grants until P34.42b moves the jobs.
3. **Services on their SAs.** Deploy scripts pass `--service-account` explicitly (AR-8); each service gets one new revision with the **same image digest** and its own SA — not a code roll; every public response stays the same.
4. **`sig-alerts` invoked with IAM (G1-11).** Remove `allUsers` invoker from `sig-alerts`; grant `roles/run.invoker` to the caller's identity (`sig-probe`'s current identity now; P34.42b moves it to `sig-probe-rt`).
5. **Proof without destruction.** Read-only IAM analysis (policy troubleshooter / `analyze-iam-policy`; verify the commands at ticket time) shows each service SA lacks delete on the spine and evidence stores and lacks other secrets; no deletion is attempted as a probe.
