# P27.7 — Empty-states, honest-gap UX & polish at national scale (P27)

- **Semantic id:** `LAUNCH.7` · **Phase:** 27 · **Kind:** ticket · **Tag:** p27-launch
- **base_branch:** `devin/p27-6-ia-redesign-landing` · **Depends on:** P27.6 (IA + design system), P27.5 (data on every page)
- **Run:** `implement-spec spec=docs/tickets/P27.7__empty-states-and-polish.md`
- **Gate status:** engineering — `web/` polish; zero-JS content preserved.

## Goal
Take the redesigned, data-wired surface to launch quality: every page reads well when data is
abundant, thin, or absent; large tables stay usable and within budget; and SIG's epistemic honesty
(gaps, contradictions, support glyphs, named denominators) is legible on real national data.

## Load (cite; do not copy)
- `docs/2_canonical_design_spec.md` §15 (web shell), the epistemic visual language (support glyph, contested marker, gap/"not researched" affordance), SIG-UI-036/037 (zero-JS), §32 (denominators/no total).
- Code: the P27.6 design system + `web/src/styles/epistemic.css`, the P27.5-wired pages, `web/src/lib/epistemic.ts`, `web/src/pages/dossier/[slug]/print.astro` (print/PDF).

## In scope — deliverables
1. **Empty / partial / gap states.** Every surface has a designed state for "no data yet", "thin
   coverage", and the per-field "not researched" gap (the clickable task affordance) — absence is
   rendered honestly, never as a blank or a fabricated zero.
2. **Large-table UX.** Build-time pagination / grouping / summarisation for the big surfaces
   (data-freshness's 210 sources; the map's tabular equivalent over tens of thousands of sites;
   coverage across many jurisdictions) — usable, sortable-by-static-links, within the a11y/perf budget.
3. **Epistemic legibility at scale.** The support glyph, contested marker, and evidence-class
   downgrades render consistently on real claims; contradictions stay visible (§3.1).
4. **Responsive + print.** Mobile/responsive polish across pages; the council-ready dossier print/PDF
   path renders the real per-jurisdiction dossier.
5. **Visual QA pass.** A consistent, elegant, launch-grade look; screenshots in the run doc for the key
   surfaces (landing, map, a dense dossier, a thin jurisdiction, freshness).
6. **Records:** `docs/build/runs/P27.7.md`, PR body.

## Out of scope
- Interactive islands / client JS (P27.9); deploy/publish (P27.8); data shapes (P27.4); new pages
  beyond states/variants of existing ones.

## Acceptance criteria
- [ ] every public surface has designed empty/partial/gap states; a thin/empty jurisdiction renders honestly (no blank, no fabricated zero) *(deterministic + agentic)*
- [ ] large tables paginate/summarise at build time and stay within the perf/a11y budget; sortable via static links (no JS) *(deterministic)*
- [ ] support glyphs / contested markers / gaps render correctly on real data; dossier print/PDF works for a real jurisdiction *(deterministic)*
- [ ] `npm --prefix web run check` green (incl. axe WCAG 2.2 AA + lighthouse budgets) in both data modes; zero-JS holds *(deterministic)*
- [ ] `make check` + build-memory green; run doc carries the visual-QA screenshots *(deterministic + agentic)*

## Cross-cutting invariants
Cited from `docs/tickets/00_MANIFEST.md § Cross-cutting invariants`: absence is a visible gap, never a
guess or a blank; contradictions stay visible; zero-JS + WCAG 2.2 AA; never publish a total; no
synthetic certainty.
