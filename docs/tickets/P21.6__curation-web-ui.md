## In scope — deliverables
1. **Curation API** (`api/src/api/curation.py`): `/v1/curation/review-queue` (list, filter by tier), `/v1/curation/review-queue/{id}/decide`, `/v1/curation/contradiction/{id}/disposition`, `/v1/curation/task/{id}/disposition`, `/v1/curation/submission` (L0 entry), `/v1/curation/revert`; bearer-token auth bound to the P16.1 contributor tiers (tier check per route); every write = one append-only row via the P21.2 repos (or `ReviewQueue`); anti-poisoning checks (`tasks.poisoning`) run server-side; audit trail row per action. Mounted only when `SIG_CURATION_ENABLED=1` (never on the public API process — `ops/docker-compose.yml` gets a second `api-curation` service bound to localhost/staging network).
2. **Curation web app** (`web/src/pages/curate/**`): server-rendered Astro pages with progressive enhancement (forms work without JS; JS islands only for keyboard shortcuts/diff views — these pages are **not** under the public zero-JS budget but are under WCAG 2.2 AA): queue list with the ER match rationale (`test_live_resolution_rationale_is_quotable_and_conformant` semantics), side-by-side entity compare, decide (match / no-match / defer with reason), contradiction disposition view (both claims, evidence, dates), task disposition, L0 submission form (evidence URL + claim + as-of; refuses without evidence), revert with reason. `lighthouserc.json` gets a separate assertion block for `/curate/**` (a11y 100, perf advisory).
3. **LLM-to-review scaffolding (SIG-LLM-*):** the queue shows any machine-suggested match/disposition as a **suggestion** with its confidence class and provenance; it can never auto-apply (test asserts no code path writes a decision without a human actor id).
4. **Tests:** `tests/api/test_curation.py` (tier enforcement, append-only, anti-poisoning refusal, no-auth 401, disabled-by-default), `web/tests/e2e/curate.spec.ts` + `.nojs` (forms submit without JS; axe AA), unit tests for the data adapters.
5. **ADR-068** (curation as a separate authenticated service; ADR-030 superseded/amended), risk register (`RISK-P21-10` curation endpoint exposed publicly → separate process + env flag + test; `RISK-P21-11` reviewer fatigue → queue ordering by tier/impact), traceability, `docs/build/CURATION_UI.md` (how to run locally, roles, screenshots as text descriptions).
