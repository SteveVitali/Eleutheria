## Goal

Stop identical source rows minting different claim ids — the defect at the root of the claim-spine inflation (≈2.2 M unresolved `camera_operated_by` claims, ≈1.9 M `located_in`). CP-1's minimal set of defects lands together: (a) `value_json` normalisation — the stored form the digest consumes is canonicalised; (b) **volatile fields leave the digest** — `valid_from` and the capture-time fields move out of `digest_base` into evidence binding (a re-observation of the same fact re-binds to the same claim, not a new id); (c) the **`obs`/`ref` distinction** — `obs` predicates carry their temporal qualifier in identity, `ref` predicates do not; (d) a `payload_version` on `value_json` — the normalisation is versioned so a future normalisation change is a declared new shape, not silent drift; (e) dedup parity — the claim-minting-diff harness (P34.44b's machinery over `ingest_claim_reconcile.csv`) proves emitted-vs-stored minting converges on next ingest. Per CP-1's explicit constraint: **no mass re-mint** — existing claims keep their ids; only new minting uses the new digest. The old duplicate rows' supersession is a later row's act (P35.23's merge/alias pass consumes what this row stabilises). The catalog's `spec_ref` list includes SIG-EPIS-009 — recorded as context (the derived-claim `derived_from_claim_ids` binding rule, which P35.25 owns); this row's identity change is what lets derived claims re-bind stably later.
