# P26.18 — Chunked-commit write path for very-large sources (P26)

- **Semantic id:** `SOURCES.17` · **Phase:** 26 · **Kind:** ticket · **Tag:** p26-sources
- **base_branch:** `devin/p26-17-robots-non-gating` · **Depends on:** P26.16 (the OSM failure is the motivating evidence, `docs/build/runs/P26.16.md`)
- **Run:** `implement-spec spec=docs/tickets/P26.18__chunked-commit-large-sources.md live_verification=true`
- **Gate status:** engineering — a write-path change; touches the append-only invariant, so the design must PRESERVE it (chunking commits earlier, never updates/deletes). No rights/robots gate involved.
- **Live stage:** land `camreg_osm_surveillance` (~1.37M claims) into the hosted spine — the source that motivated the ticket.

## Problem (measured)
`PgClaimSink.assert_claims` (`db/src/db/claim_sink.py:162-172`) wraps an entire
source's claim sequence in a single `self._conn.transaction()`. For
`camreg_osm_surveillance` (~1.37M claims) this is one ~13h+ transaction on the
`db-f1-micro` Cloud SQL instance; the P26.16 hosted run (`batch-05` exec
`nf8jl`) hit the 36h task deadline and rolled the whole thing back — the source
committed **0 claims** while every other P26.16 source landed. At current spine
size (1,059,533 claims) OSM is the single largest missing source.

## Design constraint — the append-only invariant MUST hold
The spine is insert-only (root AGENTS.md §5; `PgClaimSink`/`PgReadStore` have no
UPDATE/DELETE path). Chunking commits *earlier and more often* — it must never
introduce an update/delete, and each claim's prerequisites + evidence must land
in the SAME chunk transaction as the claim (no half-written claims across a
chunk boundary). Because writes are `ON CONFLICT DO NOTHING` and content-keyed,
a partial run that commits chunks 1..k and dies is SAFE: a re-run re-walks all
claims and the already-committed ones dedupe to +0, topping up from where it
stopped. Chunking makes big ingests *resumable*, which is strictly better than
the current all-or-nothing behaviour.

## In scope — deliverables
1. **Chunked commit in `PgClaimSink.assert_claims`.** Commit in bounded batches
   (a configurable `commit_chunk_size`, default sized so a chunk commits in
   well under the task timeout — e.g. 10k–50k claims). Each chunk is its own
   `transaction()`; a claim and all its prerequisite/evidence inserts stay in
   one chunk. The `ClaimSink` protocol contract and `SinkReport` counters
   (considered / inserted / non_claim_records / duplicates) must remain exact
   across chunk boundaries.
2. **Preserve idempotency + append-only.** Prove: (a) a full run then an
   identical re-run commits +0; (b) a run interrupted after k chunks, then
   re-run, reaches the same final count as an uninterrupted run (resumability).
   Regression tests for both, plus a test that no UPDATE/DELETE is issued.
3. **Ops surface.** The scheduled-ingest/runner path should thread the chunk
   size (env/config, not hard-coded); default applies to all sources
   (small sources commit in a single chunk, unchanged behaviour). No new
   delete path anywhere.
4. **Hosted proof — land OSM.** Rebuild the image (Cloud Build — Docker daemon
   down), redeploy `sig-ingest-camreg-batch-05` (or a dedicated
   `sig-ingest-camreg-osm` single-source job) with the chunk size set, run
   `camreg_osm_surveillance` to completion, and verify the ~1.37M claims land.
   Then prove the idempotent re-run (+0). Record the true spine delta.
5. **Records.** `docs/build/runs/P26.18.md`, PR body, BUILD_INDEX row 115,
   LEDGER phase log; close the OSM-commit deferral opened by P26.16
   (D-SOURCES.12-1 hosted-apply remainder / a new D-SOURCES.17-x if cleaner);
   ladder re-measured with OSM landed.

## Out of scope
- Scaling the Cloud SQL instance (the fix is the write path, not the hardware —
  though the ticket may note an instance bump as an alternative in the run doc);
  reconciliation/resolution changes; changing what OSM emits.

## Acceptance criteria
- [ ] `assert_claims` commits in bounded chunks; `SinkReport` counters exact across boundaries; no UPDATE/DELETE path added *(deterministic)*
- [ ] idempotent full re-run (+0) AND interrupted-then-resumed run reaches the same count as uninterrupted *(deterministic — testcontainer or fixture-driven)*
- [ ] `camreg_osm_surveillance` (~1.37M claims) lands in the hosted spine; idempotent hosted re-run proven +0 *(live-gated)*
- [ ] `make check` + build-memory green; ladder re-measured *(deterministic)*

## Cross-cutting invariants
Cited from `docs/tickets/00_MANIFEST.md § Cross-cutting invariants`: append-only —
chunking commits earlier, NEVER updates/deletes; content-digest idempotency
holds across chunk boundaries and interrupted resumes; verbatim literals; a
claim + its evidence commit atomically within one chunk.
