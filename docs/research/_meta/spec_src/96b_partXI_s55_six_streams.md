# Part XI — Evidence integrity and investigation completion

## 55. Round-10 contract extension (2026-09-25)

### 55.1 Scope, precedence and execution authority

This additive extension is recorded by ADR-120, under the operator’s request for six fully researched follow-up streams. It defines future implementation obligations; it is not evidence that they are implemented, that human labels exist, or that a source/publication gate is signed. Existing Part VIII protections, frozen package layout, P31 ownership and operator decisions remain binding. Where this extension tightens a current implementation (notably provenance, identity and evaluation), migrate additively with the explicitly gated rollout described here; preserve historical decisions and disclosures.

The design rationale and typed shared interfaces are `docs/build/planning/2026-09-25-six-streams/DESIGN.md`; primary-source and code research is in its `research/` directory. `docs/build/planning/2026-09-25-six-streams/PLAN.json` and `REQUIREMENTS.csv` map every new requirement to exactly one contract in `docs/tickets/00_MANIFEST.md`. Research notes propose examples; these normative paragraphs and the final design control the implementation when earlier draft suggestions differ.

Execution sequence: reconcile landed P31 → integrity/tooling and independent engineering → freeze repaired snapshot → human development labels and dossier semantic review → freeze candidate then draw its confirmatory sample → independent blinded final campaign → one evaluation without holdout leakage → rematerialize every final artifact → verify one candidate → human publication gate → publish → full independent capstone/reconciliation/documentation tail. The evaluator and memory events remain shadow-only until their recorded activation/cutover decisions. No planning operation advances another active ledger.

Architecture decision: retain Astro plus the three named map/search/network React islands. Add release-specific read-only SQLite FTS5 search through the existing API package with no-JS HTML and complete static browse/records; use separate, gated anonymous intake storage and a restricted correction application bridge. No general SPA, new basemap, account system or search cluster is selected. Bounded cost/latency/storage benchmarks precede deployment; failure requires a measured alternative ADR, not silently reduced corpus coverage.

### 55.2 Evidence, semantics and temporal integrity

**SIG-TRUST-001 (MUST).** The production assertion interface must preserve typed value, raw lexical value, unit, scope, valid time, epistemic axes, sensitivity, compartment and derivation/correction links. Defaults require a named versioned mapping and an explicit basis; absent fields must not silently become stronger evidence or lower sensitivity. Unknown predicate/type combinations fail closed or enter an explicit quarantine, without making an otherwise valid entity disappear. Owner: P32.2.

**SIG-TRUST-002 (MUST).** Every newly asserted claim and live re-sighting must bind the actual captured artifact consumed by extraction, including digest, retrieval time, extractor/config identity and a typed locator or an explicit document-only limitation. Replay retains original observation time and separately records replay assertion time. Legacy synthetic provenance remains identified as legacy; exact replayability must be measured, not inferred from source_id presence. Owner: P32.2.

**SIG-TRUST-003 (MUST).** Publishers, hosts, operators, owners, vendors, prime contractors, funders and access partners must remain distinct roles unless evidence explicitly relates them. Templates, recommendations, awards, subscriptions and deployments retain their different legal/operational status. Count comparison requires compatible subject, capability, population, geography, time and measurement basis; approximate derived sums preserve their inputs, arithmetic and uncertainty. Owner: P32.3.

**SIG-TRUST-004 (MUST).** Organization resolution must prefer scoped external identifiers and treat normalized-name-only identities as review candidates when jurisdiction or institutional scope is unknown or ambiguous. Repairing an existing false union or split must append reviewed identity dispositions and stable-id redirects; it must not overwrite historical entities, keys or claims. A source publisher label is not an identity proof for the observed operator. Owner: P32.3.

**SIG-TRUST-005 (MUST).** Resolver, reconciliation, camera-site materialization, API and export must share one versioned temporal eligibility contract. Eligible occurrences are bounded by belief time and asserted valid-world time; retrieval-time fallback is labeled. Select the latest establishing occurrence within each source assertion/source-record lineage, preserving concurrent independent candidates and atomic fields; explicit resolution policy chooses or abstains. Selection uses occurrence time and deterministic tie-breakers, not claim-id order. Later captures cannot alter a past-belief answer, and A→B→A, replays, corrections and equal timestamps must have cross-consumer conformance tests. Owner: P32.4.

**SIG-TRUST-006 (MUST).** Every public consumer, including indexes, tiles, analytics and relationship endpoints, must apply the same reviewed eligibility/disposition policy. Publication-review flags, sensitivity, rights restrictions and correction/withdrawal state must be consumed, with a recorded policy version and reason. Withheld endpoints cannot leak through labels or edge topology. Historical claims remain append-only; legitimate public withdrawals yield an honest policy-controlled tombstone. Current access withdrawals override historical availability during activation, rollback and every operator-controlled origin/cache/artifact path; deny an unsafe whole artifact rather than rewrite bytes under its identity. Owner: P32.5.

**SIG-TRUST-007 (MUST).** A historical provenance and semantic audit must report a reproducible sampling frame and denominators for exact replayability, locatability, unsupported role mappings, count comparability and publication eligibility. Recovery requires preserved bytes plus provable lineage; unavailable evidence is reported explicitly and cannot be reconstructed by pretending a new fetch is the old capture. Repairs are bounded, resumable, dry-runnable and append-only. Owner: P32.6.

### 55.3 A three-dossier acceptance portfolio

**SIG-DOS-001 (MUST).** Each research dossier must answer a fixed schema covering capability, owned/accessed hardware, actors and roles, procurement/funding, legal/operational authority, retention, access/sharing, use/oversight, decision dates, changes and unknowns. Every answer has scope/time and a supported, disputed, derived, unknown, withheld or not-applicable state with evidence; absence of an answer is not evidence of absence. Owner: P32.17.

**SIG-DOS-002 (MUST).** Dossier completion requires a fact-to-capture ledger, source search log, comparability review, currentness assessment and an independent adversarial check of every answer class. Publication is blocked by unsupported affirmative claims, misclassified instruments or unconsumed restrictions. Honest documented unknowns are permitted and must generate specific follow-up tasks rather than artificial completeness scores. The pilot uses the fixed twelve-question S2 rubric: at least 28/36, questions 1/5/7/8 at least 2, with material governance/contract/relationship assertions independently reviewed. Incomplete publication is a distinct explicitly accepted scope and does not satisfy pilot completion. Owner: P32.17.

**SIG-DOS-003 (MUST).** The Oklahoma City dossier must distinguish city-owned cameras, private city cameras, metro observations and partner-agency access; label the approximate derived city sum and do not display it as contradictory to a metro count. It must separately establish dates/scope of retention and sharing provisions, renewal terms and applicability of UVED law, preserving exceptions and unknowns. Secondary reports cannot be labeled executed contracts or council minutes. Owner: P32.18.

**SIG-DOS-004 (MUST).** The Tulsa dossier must separate the public private-camera MOU template from any demonstrated executed agreement, distinguish policy effective dates from capture dates, and leave unsupported counts, spend, sharing and usage unknown. A template proves terms offered, not adoption or an active partner relationship. Completeness includes a precise request/research plan for unavailable facts without sending it automatically. Owner: P32.19.

**SIG-DOS-005 (MUST).** The San Diego dossier must distinguish the physical ALPR/streetlight system from subscription-only access to external plate data, identify prime/subcontractor roles only with evidence, and separate annual self-report, oversight recommendation and enacted policy. Network audit data receives a structural Part VIII preflight before any row-level acquisition; public aggregate evidence never licenses person/plate ingestion. Owner: P32.20.

### 55.4 Independent human evaluation

**SIG-EVAL-001 (MUST).** Resolution evaluation must use a preregistered campaign with a frozen source snapshot, explicit target population, sampling frame, inclusion probabilities, strata, grouping, split assignment, seed and ruleset identity. Training, calibration and sealed test sets must be separated at entity/component and duplicated upstream-record lineage boundaries; whole source families are held out when claiming unseen-family generalization. A changed model or unblinded test set requires a new evaluation decision; tuning on the test set is prohibited. Owner: P32.9.

**SIG-EVAL-002 (MUST).** Independent human labels must be recorded append-only with pseudonymous reviewer identity, evidence references, reason and one of same-device, different-device or insufficient-evidence. Reviewers are blinded to model/previous-label predictions during first pass; two independent labels and an adjudication process preserve disagreements and abstentions. Evaluation labels are distinct from operational accept/reject decisions; agents and LLMs cannot impersonate human adjudication. Owner: P32.9.

**SIG-EVAL-003 (MUST).** Reports must distinguish auto-positive precision, candidate-generation recall, whole-cluster quality and labelability. They must state numerator, denominator, sampling weights, uncertainty method and population limits. Unresolved/missing evidence cannot be dropped to improve a gate. Correlated pairs and enriched diagnostic samples cannot be treated as independent representative Bernoulli trials without a justified design; a pair sample alone cannot establish whole-cluster recall. Owner: P32.10.

**SIG-EVAL-004 (MUST).** Auto-write eligibility must use a preregistered lower confidence bound of at least 0.98 on strict precision for each authorized tier, with simultaneous-error control across tested tiers and a fixed sampling/stopping rule. Insufficient evidence demotes or retains provisional/review-only status. The interval method must match the sampling design; point estimates, favorable resampling and optional stopping cannot establish eligibility. LLM agreement is supplementary, never a substitute for human ground truth. Owner: P32.10.

**SIG-EVAL-005 (MUST).** A rule/threshold candidate must be derived only from development/calibration data and frozen before its confirmatory sampling frame is drawn. After the independent final campaign, evaluate that fixed candidate once, with a new ADR recording losses, coverage, uncertainty, failures and rollback. Further candidate changes after unsealing require a new independent frame/sample/campaign. Human decisions must be verified through the P31 review-to-clustering seam; failed/inconclusive assessments retain provisional disclosures and owed deferrals. Owner: P32.23.

**SIG-EVAL-006 (MUST).** Published evaluation claims must identify exactly the tiers, populations, geography/source mix, model/ruleset and time window supported by the assessment. Drift in input mix, extraction semantics or matching rules triggers reassessment; successful evaluation of selected camera-site tiers cannot certify organization identities, all graph edges or overall surveillance coverage. Owner: P32.23.

**SIG-EVAL-007 (MUST).** Select and freeze the candidate matcher using development/calibration evidence before defining and drawing its confirmatory auto-positive sampling frame. Pin ruleset, eligible edge/tier populations, inclusion probabilities, grouping, sample sizes, seed and hypothesis family before final human labeling. A candidate change that introduces different positives invalidates the old frame; freeze and redraw a new independent assessment rather than carry unsupported inclusion probabilities. Development and final human work have separate markers/readouts. Owner: P32.22a.

### 55.5 Released discovery, citations and correction

**SIG-FIND-001 (MUST).** Public records and citations must bind an immutable release manifest pinning input snapshot, code, ontology, policy, ruleset, world/belief cutoffs, compartment licenses, artifact digests and completeness. A pre-render namespace hashes canonical ID-free projection roots and interpretation/renderer inputs; a separate final integrity digest covers emitted artifact checksums, avoiding self-reference. Serialization and atomic latest-pointer publication are specified. Release-specific content never silently changes; a withdrawn or unavailable artifact returns an honest tombstone or unavailable state. Owner: P32.13.

**SIG-FIND-002 (MUST).** Every eligible public record must have a release- and compartment-specific stable route and evidence/claim anchors, with no-JS access. A citation resolves the represented released bytes and interpretation. Unsupported historical selectors are explicitly rejected or mapped to a real release; an ignored query string cannot masquerade as an as-of answer. Record materialization costs must be measured before production rollout. Owner: P32.13.

**SIG-FIND-003 (MUST).** Search must cover all eligible records in the selected release and compartment, including records without locations, with named totals, exact-id lookup, bounded pagination and specific record links. Index construction and query serving preserve compartment/suppression boundaries and release consistency. Full-corpus discovery cannot be implemented as an unlabeled first-N sample or a current-only API behind a historical page. Owner: P32.14.

**SIG-FIND-004 (MUST).** The existing map/search/network islands must share versioned URL state for release, compartment, query, filters and focused record, restore browser navigation and link to equivalent static records/lists. Connections expose qualified edge evidence and bounded expansion; map proximity and graph reachability cannot imply identity or observed access. P31 tile/compression work and the no-basemap decision remain in force. Owner: P32.15.

**SIG-FIND-005 (MUST).** Public static routes and no-JS pagination must meet the existing 150 KiB/zero-script budget; enhanced routes use explicit per-island budgets and retain complete equivalent navigation. Real-sized release fixtures, WCAG 2.2 AA checks, keyboard flow, back/forward state and missing-location records are required acceptance cases. Budget failures must be repaired or explicitly decided, never hidden by testing only demo data. Owner: P32.15.

**SIG-FIND-006 (MUST).** Anonymous correction intake must provide a durable receipt and restricted moderation workflow independent of claim-spine writes. The first receiver accepts bounded allowlisted fields without uploads or server-side URL fetches, minimizes personal data, enforces abuse/retention controls and preserves reviewer-only publication decisions. Public status/log views contain redacted reviewed dispositions, not raw submissions or private receipt/contact information. Owner: P32.16.

**SIG-FIND-007 (MUST).** The public acceptance portfolio must demonstrate place-to-record-to-evidence, relationship-to-qualified-claim, immutable citation and correction-to-reviewed-disposition journeys on the three dossiers and records outside the old sample. Results distinguish automated conformance, agent walkthroughs and actual independent user testing; missing user participation cannot be represented as usability validation. Owner: P32.24.

**SIG-FIND-008 (MUST).** An authorized moderation decision must have an idempotent, audited bridge to the canonical append-only correction/disposition workflow, recording submission, proposal, validation, applied assertion/disposition and resulting release identities. The public receiver has no authority to apply it. A receipt is not a correction, and review completion is distinct from application and publication; crashes/retries cannot duplicate or bypass any transition. Owner: P32.16a.

### 55.6 Gap-driven source acquisition

**SIG-ACQ-001 (MUST).** Source discovery must start from a named evidence/question/relationship gap or justified national need, record search provenance and access checks, and distinguish existing registry entries, planned P31 work, mirrors and genuinely new candidates. Candidate value is measured as supported new relationships or closed gaps after deduplication, not raw claim volume. Owner: P32.11.

**SIG-ACQ-002 (MUST).** A candidate must carry authority, target predicates, scope/time, lineage independence, extractability, refresh cost, rights basis and Part VIII preflight before prioritization. Rights and sensitive-data barriers are hard gates, not scores that usefulness can offset. Raw document licensing, factual extraction and public derived-artifact licensing must be assessed separately; municipal publication alone does not imply federal public-domain status. Owner: P32.11.

**SIG-ACQ-003 (MUST).** New acquisition adapters must use the existing connector stages, typed assertion contract, capture store and fail-closed loader. Fixtures must include templates versus executed instruments, publication versus effective dates, subscriptions versus hardware, contractor roles, exceptions and missing/redacted fields. New source rows default to ingestion_permitted=false; fixture success neither clears rights nor proves live access. Owner: P32.12.

**SIG-ACQ-004 (MUST).** A bounded source pilot must publish selection rationale, actual access/capture/extraction/link/publication funnel, unique evidence-lineage contribution, review burden, cost and maintenance outcome. A stop/continue decision must use measured gap closure and failure reasons. Sources owned by P31 are consumed or improved rather than onboarded a second time, and no public-records request or outreach is sent without explicit authority. Owner: P32.21.

### 55.7 Current build memory and closeout reliability

**SIG-MEM-001 (MUST).** At a round boundary, reconcile the actual landed predecessor against the proposed dependency map and record demonstrated defects, hypotheses, already-closed seams and still-owed work separately. A planning branch must not advance another active orchestrator’s control state. Every new requirement has exactly one implementation owner and an explicit verification domain. Owner: P32.1.

**SIG-MEM-002 (MUST).** Current obligation and requirement assessments must be derived from explicit evidence-backed transitions, retaining historical statuses and scope-specific assessments. Conflicting legacy status text requires recorded reconciliation; ambiguity stays open. A deterministic current-state view records input hashes and revision, separates fixture/DB/hosted/public evidence, lists every outstanding owner/landing, and detects stale inputs without modifying the control ledger. Owner: P32.7.

**SIG-MEM-003 (MUST).** Build validation and closeout must be safe across worktrees: reports have unique or caller-selected destinations and input identities; control writes use expected-state preconditions and a scoped single-writer protocol. Idempotent recovery keyed by ticket, implementation revision and PR identity must handle interruption between code and memory commits without duplicate advancement, duplicate PR creation or invented closure. Every worker and orchestrator repair path shares one authoritative chain-head check and a prepared/external-known/memory-committed/acknowledged operation protocol. Atomicity is at a validated git tree/commit, not arbitrary uncommitted files; workflow activation stays shadow-only until a verified operator-approved cutover. Owner: P32.8.

**SIG-MEM-004 (MUST).** Repository and agent guidance must state the current implemented architecture and the governing ADR supersession chain, with tested command references. Compact orientation views must preserve links to obligations and full history; they cannot replace mandatory ticket loads or erase uncertainty. Documentation refresh follows actual implementation and validates the nearest-file instruction hierarchy. Owner: P33.8.

### 55.8 Activation, verification and publication

**SIG-TRUST-008 (MUST).** Production recovery and activation must execute from a reviewed, resource-bounded plan with pinned code, input selection, before/after inventory, idempotence proof and rollback via new dispositions or prior released artifacts. Source-rights and operational approvals remain binding. Calendar-dependent checks, including the reserved 2026-10-10 replay, cannot be marked complete before their observed execution. Owner: P32.22.

**SIG-TRUST-009 (MUST).** A new public release requires a complete release candidate, change/withholding summary, verified source and publication authority, evaluation disclosure, tested intake operating ownership, and the existing human publication gate. Publication must be atomic, followed by unauthenticated verification against expected digests and a tested prior-release rollback. A planning artifact, successful build or agent judgment cannot sign this gate. Owner: P32.25.

**SIG-TRUST-010 (MUST).** After the final evaluation decision, materialize the selected or safely demoted rules against the frozen approved inputs and regenerate all affected graph, dossier, record, index, tile and analytics artifacts into one new release candidate. Every artifact must pin the same evaluation result, ruleset and snapshot. Pre-evaluation previews cannot satisfy release acceptance; any changed evaluation-relevant inputs require an explicit reassessment decision. Owner: P32.23a.

### 55.9 Traceability and explicit human obligations

New requirement rows enter COVERAGE_MATRIX as MISSING with ticket routing; planning does not turn them MET. Existing assessments remain dated historical evidence. D-R6.1-EVAL and the human portions of D-P30.2b-1/-2 move to the explicit HUMAN-H4/P32.22a/HUMAN-H5/P32.23 path without being closed. P31 source/publication and calendar obligations retain their original authorities and evidence. The research candidate inventory records review depth and uncertain availability; a listed URL is not ingestion clearance.

HUMAN-H4 records human development/calibration labels and separate documentary semantic review; P32.22a freezes the candidate and its sampling frame; HUMAN-H5 records final blinded confirmatory adjudication. GATE-G3 exercises HG-11 for the concrete release and receiver operating packet. GATE-ACCEPT records Round-10 capstone acceptance. Source rights, resource changes, workflow-writer cutover and independent usability work remain separately scoped decisions/return paths. Neither an agent-generated label nor an incomplete dossier may satisfy the human/pilot gate by relabeling it complete.
